# ADR-0025：GPU 已分配内存和建议上限

状态：已采纳（#230）。取代 [ADR-0004](0004-gpu-accelerator-stats.md) 里「不取已分配字节」和「没有容量条」。仍不把物理内存当成显存总量。仍不读 Metal 性能计数器，不调用 `IOServiceOpen`，不使用 `powermetrics`。不改变占用内存的节点选择，也不把已分配字节拿去代替占用内存。

## 背景

GPU 占用内存是正在占用的统一内存。驱动另外公布已经分配的系统内存。`MTLDevice.recommendedMaxWorkingSetSize` 是系统给这颗 GPU 的建议工作集上限，不是一块独立显存的大小。ADR-0004 当时不取已分配字节，页面上也不画条，所以看不出占用离建议上限还有多远。

## 决定

- 「已分配」取被选中那块加速器的 `Alloc system memory`。必须是字节数，否则「—」。真实 0 是「0 字节」。和占用内存同一台，不向另一台借。
- 建议上限只读 `MTLDevice.recommendedMaxWorkingSetSize`。读取放在 Darwin 读取器 `HostGPUMemoryLimitReader`，不进可移植库。不读 Metal 性能计数器。
- 占用和建议上限都有时，画一条占用除以建议上限的进度条，标注「建议上限 X」。缺一个就不画。比例超过 1 时条画满，占用和建议上限的文字仍写真实字节。建议上限为 0 时，占用也是 0 则条是空的，占用大于 0 则条画满。
- 不出现「总量」。不把物理内存当成这条上限。
- 已分配和建议上限不进菜单栏、快照、本机历史或本机页卡片。

## 后果

- GPU 占用内存卡片多一个「已分配」小标签，以及可选的建议上限条。
- 建议上限读不到，或占用内存读不到，卡片上没有这条。
- 快照和本机页仍只有 GPU 使用率和 GPU 占用内存。

## 不考虑

- 把已分配字节当成占用，或把多台加速器的已分配相加。
- 用物理内存或「显存总量」当上限。
- 读 `MTLCounter`、`MTLCounterSampleBuffer` 或其它 Metal 计数器来画这条。
