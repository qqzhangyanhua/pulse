# ADR-0018：Sparkle 更新只在询问后检查

状态：提议（#200）。提议不是现行行为，不要写进 `docs/TECH.md`。本条收窄 [ADR-0005](0005-manual-public-ip-request.md)「这是 Pulse 的第一次出站请求」和「启动不请求」这两句，不改写那篇。「这是 Pulse 的第一次出站请求」不再覆盖每一次出站请求。公网 IP 仍只在用户点击「查询公网 IP」之后才查。更新检查是第二种，而且只有用户允许之后才有。「启动不请求」仍约束公网 IP。用户允许更新之后，启动可以交给 Sparkle 做一次检查。启动仍然不查询公网 IP。不改变 [ADR-0001](0001-process-memory-footprint.md) 的内存占用，不改变 [ADR-0002](0002-process-energy-wakeups.md) 的能耗和唤醒，不改变 [ADR-0003](0003-thermal-state-api.md) 的热状态来源和对 `IOServiceOpen` 的禁止，不改变 [ADR-0004](0004-gpu-accelerator-stats.md) 的 GPU 读数，不改变 [ADR-0006](0006-location-for-wifi-name.md) 的定位权限，不改变 [ADR-0007](0007-chip-temperature.md) 的芯片温度。已采纳的曲线、历史、外部命令和功耗频率也不改。分发仍是 Developer ID 加公证，不是 Mac App Store。

## 背景

Pulse 今天只有一种出站请求：用户点「查询公网 IP」之后，用一次性会话问地址。启动不请求，采样不请求，没有轮询。

检查更新是另一件事。它要向外看有没有新版本，再下载安装包。不经询问就在启动时连出去，用户不知道这次访问。#182 对本项的约束是：Sparkle 会自动联网，必须补充 ADR-0005；默认先问，并且可以关掉。

直装是 Developer ID，经 `scripts/notarize.sh` 提交公证，再由 stapler 装订票据。不是 Mac App Store。主 App 不开沙盒。Team ID 只在环境变量 `DEVELOPMENT_TEAM` 里，不进仓库。脚本拒绝在 `bash -x` 下运行，以免打出公证密码；证书、Apple ID 和 app 专用密码也不进仓库。脚本先打 zip 交给 notarytool，装订发生在提交之后，所以交给公证的那份 zip 里还没有装订票据。`v*` 标签上传的 zip 没有公证，不能当可更新的包。

## 决定

- 更新检查是第二次出站请求，和公网 IP 分开。不借 IP 那次请求查版本，IP 查询也不捎带查更新。ADR-0005 的点击规则保持不变。
- 默认不检查。状态只有三种：还没问过、拒绝、允许。不是允许，就不检查，也不建立更新连接。
- 第一次检查之前先问。同意变成允许，拒绝变成拒绝。关掉问题、没有回答，就仍是还没问过，这次不检查；下次启动再问，仍不连出去。拒绝之后不自动检查。
- 设置可以把允许改回拒绝，也可以把拒绝改成允许。关掉就是拒绝：没有任何更新连接，也不能从菜单再查一次。要再查，先在设置里打开。
- 采样不检查。允许之后，只在启动时交给 Sparkle，每次启动最多一次。间隔用 Sparkle 自己的：没到间隔就不查。不自己写轮询，也不在 App 开着的时候再加一个定时器。
- Info.plist 里可以写 feed 地址 `SUFeedURL` 和公钥 `SUPublicEDKey`。写在里面不等于发出请求。还没允许时，不创建更新器。
- 签名只用 Sparkle 的 EdDSA，不用已经弃用的 DSA。私钥放在公证那台机器的钥匙串里，或放在 CI 密钥里，不提交。公钥可以进仓库。私钥、Team ID、公证密码不是同一件东西，都不进仓库。
- Appcast 是本仓库 GitHub Release 上的附件：`https://github.com/qqzhangyanhua/pulse/releases/latest/download/appcast.xml`。更新包也是同一次 Release 上的附件。不另建服务器，也不换到别的主机。
- 装订完成之后，再把用户会下载的那一份 zip 或 dmg 交给 Sparkle 的 `sign_update`。签的是装订之后重新打出来的包，不是交给 notarytool 的那份尚未装订的 zip。然后写出 appcast 条目。脚本仍拒绝 `bash -x`，仍不打印密钥。私钥缺失时，在上传到 GitHub Release 之前失败，不发出没有 EdDSA 签名的更新包。
- 不静默替换正在运行的 App。找到更新时用 Sparkle 自带的更新界面。用户还没同意检查，就不下载。同意检查不等于在背后安装。
- 可更新的包只来自 Developer ID 签名、公证并装订之后的那一份。ad-hoc 包和未经公证的标签包不进 appcast。主 App 仍不开沙盒，也不改成 Mac App Store 证书。定位权限那一项 entitlement 仍只在主 App。

## 后果

- 用户没同意之前，没有更新连接。同意之后，启动时按 Sparkle 的间隔最多查一次。
- 拒绝或之后关掉，就不再连接更新地址，也不下载。
- 不点「查询公网 IP」，就仍然没有那一次地址请求。两次出站互不触发。
- 本条在被采纳之前只是提议。不要把它写成 `docs/TECH.md` 里的现行行为。采纳之后才改 RELEASE.md，说明 appcast、装订之后的 `sign_update`，以及私钥缺失就不上载。

## 不考虑

- 不静默安装，也不在用户没同意检查时后台下载。
- 不自己写检查循环，也不从采样里发更新请求。
- 不另建更新服务器。不做差分包。
- 不上 Mac App Store。沙盒里做不到强制退出，也读不到其它进程。
- 不把 EdDSA 私钥写进仓库，也不用 `bash -x` 跑公证脚本。
- 授权校验、买断和 Setapp 不在本条。那些若要联网，先改它们自己的决定，并再补充 ADR-0005。更新请求不捎带许可证检查。
- 不打开本机监听端口。无障碍基线和首次启动引导不在本条。

## 后续实现 ticket

### 1. 更新检查的三种选择

- 阻塞：无
- 交付：选择只有「还没问过」「拒绝」「允许」。不是「允许」就不检查，也不连接。未回答仍是「还没问过」。设置只能在「拒绝」和「允许」之间改。
- 测试接缝：纯状态机。抓住三种选择怎么变，以及「不是允许就不检查」。放掉 Sparkle、网络和界面文案。

### 2. 第一次询问和设置开关

- 阻塞：第 1 张
- 交付：第一次检查前先问。文案只说明会向外看有没有新版本，以及可以拒绝。不写危险、过期或必须更新。设置里可以关掉。关掉之后没有更新连接。
- 测试接缝：WiringSourceTests。抓住询问和开关的中文仍是冷静的，以及关掉就是不连接。放掉 Sparkle 是否真的发出请求。

### 3. 只有允许时才调用 Sparkle

- 阻塞：第 1 张
- 交付：只有「允许」时，启动才交给 Sparkle，按它自己的间隔，每次启动最多一次。还没问过、拒绝或之后关掉，都不调用。采样不调用。没有同意检查，就不下载。
- 测试接缝：WiringSourceTests 锁住调用点只在允许时出现；纯状态机锁住「不是允许就不检查」。抓住采样路径不会发出更新请求。放掉 Sparkle 框架内部的下载和界面。

### 4. 装订之后生成 appcast 条目

- 阻塞：第 3 张
- 交付：用版本、长度和 EdDSA 签名生成一条 appcast 条目。公证脚本在装订之后使用这个结果，签的是用户会下载的那一份。私钥缺失时，在上传之前失败。脚本仍拒绝 `bash -x`，仍不打印密钥。
- 测试接缝：纯构建器。抓住版本、长度和签名能变成那一条目的文本；缺长度或签名就不是可发布的条目。放掉真正的签名工具、钥匙串和上传。RELEASE.md 等本 ADR 成为已采纳之后再改，算在这一张里。
