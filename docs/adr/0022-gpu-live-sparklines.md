# ADR-0022：GPU 功耗和频率各有一条实时小曲线

状态：已采纳（#227）。取代 [ADR-0021](0021-gpu-frequency-weighted.md) 里「GPU 功耗和 GPU 频率不进曲线」。不改频率的停留加权，也不改 [ADR-0020](0020-gpu-power-energy-channel.md) 的功耗通道。仍不进本机历史。使用率曲线仍按 [ADR-0008](0008-gpu-history-keeps-recording.md) 在每一页记录，离开不删。

## 背景

功耗和频率现在是卡片上的一个数。一下子冲高和一直偏高看起来一样。把它们写进使用率曲线或本机历史会混进口径，也会改数据库结构。

## 决定

- GPU 功耗卡片和 GPU 频率卡片各自内嵌一条实时小曲线。不是使用率曲线，也没有范围开关。
- 每条最多 90 点，先例是 `SystemCPUHistory`。少于 2 点不画。与最后一点同一采样时间不追加。
- 只在 GPU 页可见时追加。[ADR-0012](0012-energy-model-power-frequency.md) 的「只在 GPU 页被选中时读」不变，不因此在别的页打开 Energy Model。
- 离开 GPU 页清空这两条。再次进入从空曲线重新记。不清使用率曲线。
- 缺失不追加，也不存成 0。功耗的缺失是 nil 或非有限数。频率的缺失是 `.missing`、非有限或负数赫兹。
- 「空闲」（`GPUFrequency.idle`）不追加，不画成 0。真实 0 W 和真实 0 Hz（`.hertz(0)`）仍是点。
- 不写入 `HistorySample`，不改 `HistoryStore` 的建表和插入，不迁移数据库。没有功耗列，也没有频率列。
- 不进菜单栏、快照、本机页 GPU 卡片或进程表。

## 后果

- 停在 GPU 页时能看出功耗和频率是冲一下还是持续高。
- 离开再回来，小曲线是空的，中间离开的时间不会被画成 0。
- 历史库结构不变。

## 不考虑

- 把小曲线写进本机历史，让「1 小时」也能看功耗：要改表，而且离开页面的缺口会和「只在可见时读」缠在一起。
- 把「空闲」画在 0 Hz：空闲不是 0，会把关机画成一条贴底的线。
- 离开时保留小曲线：没在看的时间会留在图上，或在回来时把缺口补成旧值。
