# ADR-0024：GPU 页用活跃屏的当前模式显示刷新率

状态：已采纳（#229）。这是新的数据源，不改变 [ADR-0004](0004-gpu-accelerator-stats.md) 的使用率和占用内存，也不放开它对 `IOServiceOpen`、Metal 计数器和 `powermetrics` 的禁止。不改变 [ADR-0008](0008-gpu-history-keeps-recording.md) 的曲线，也不把显示器写进本机历史。不改变 [ADR-0009](0009-gpu-process-share.md) 的 GPU 占比。不改变 [ADR-0012](0012-energy-model-power-frequency.md)、[ADR-0020](0020-gpu-power-energy-channel.md) 和 [ADR-0021](0021-gpu-frequency-weighted.md) 的功耗与频率。不改变 [ADR-0026](0026-gpu-snapshot-machine-card.md)：快照和本机页的 GPU 卡片仍只有使用率和占用内存。

## 背景

接了几块屏、刷新率是多少，常常能解释 WindowServer 为什么占着 GPU。这块信息不在加速器的性能统计里，也不该跟着每一拍采样去问。可变刷新率的当前模式会报 0 Hz，把 0 直接写出来会把「最高能到多少」说成没有刷新率。

## 决定

- 新的读取器只在 Darwin 上编译。它读 CoreGraphics 的活跃屏列表和当前显示模式，再从对应的 `NSScreen` 取 `maximumFramesPerSecond`。读到的数交给可移植的投影。投影不调用 CoreGraphics。
- 只在进入 GPU 页时读一次。这一页还开着时，屏幕参数变化通知再读一次。不进主采样拍，不另开计时器。离开这一页就卸下通知。已经显示的卡片留着，下次进入再读。
- 每块活跃屏一行。内建屏排在外接屏前面，同一类保持读取顺序。一行是内建或外接、像素分辨率、当前模式的刷新率。
- 模式刷新率是有限且大于 0 的数时，就显示这个数，不用最高刷新率替换。整数不带小数。
- 模式刷新率是 0（可变刷新率）时，改用这块屏的 `maximumFramesPerSecond`。这个数缺失、为 0 或为负，这一格是「—」，不写成 `0 Hz`。
- 模式刷新率读不到、为负或不是有限数时，这一格是「—」。这种情况不用最高刷新率填。模式复制不到时，像素宽和高留空，不写成 0。像素宽或高缺失或不是正数时，分辨率是「—」，不写成 0。
- 没有屏幕信息（列表读失败，或没有活跃屏）时，整张卡是「—」，不是一行空屏。
- 不进本机历史、菜单栏或快照。本机页的 GPU 卡片不加这一项。

## 后果

- GPU 页在「最近 1 小时 GPU 时间」下面有一张「显示器」卡片。
- 插上、拔下或改分辨率时，人还停在这一页，卡片会更新。停在别的页时不读；回到 GPU 页时再读。
- 不要为了这一张卡去改采样拍、历史库或快照字段。

## 不考虑

- 把 0 Hz 显示出来，或把任意一块屏都写成它的最高刷新率。
- 每一拍都读屏幕。分辨率不会按采样间隔变。
- 把睡眠中的屏或镜像副本算进活跃屏。活跃列表里没有的，就不显示。
