# ADR-0023：最近 1 小时 GPU 时间用内存里的分钟账本

状态：已采纳（#228）。取代 [ADR-0009](0009-gpu-process-share.md) 里「离开 GPU 页就不读 AGX 客户端」。不改变 GPU 占比的排名、缺失、「—」和超过 100% 的规则：占比仍只在 GPU 页更新，离开期间的样本仍不当成占比基线，离开也不清掉已经显示的占比卡。不改变 [ADR-0008](0008-gpu-history-keeps-recording.md) 的整机使用率。不把 GPU 时间写入菜单栏、快照或本机历史。仍不调用 `IOServiceOpen`。

## 背景

GPU 占比只回答最近一拍是谁在用。人离开 GPU 页再回来，看不到这一小时里是谁把 GPU 跑满的。ADR-0009 把 AGX 客户端的读取绑在「这一页可见」上，所以离开期间没有样本可以累加。

累计时间已经写在 `AGXDeviceUserClient` 的注册表属性里。要跨页保留一小时，就得每一拍都读，不能等用户打开 GPU 页。

## 决定

- 每一拍、在每一页都读 `AGXDeviceUserClient` 已经公布的属性，读法和 ADR-0009 相同：pid 来自 `IOUserClientCreator`，累计时间来自 `AppUsage` 的 `accumulatedGPUTime`。不调用 `IOServiceOpen`，不打开用户客户端。
- 读数进一份可移植的、只在内存里的分钟账本。进程身份是 pid 加启动时间。保留 1 小时，最多 60 个桶。不落盘。退出 Pulse 就清空。
- GPU 页在曲线和「GPU 占比」下方、「频率分布」之后加卡片「最近 1 小时 GPU 时间」。取合计前 5 名，单位秒，一位小数，例如「12.3 秒」。合计相同则 pid 较小的在前。还没有 AGX 样本，或账本还没有计入的进程时，卡片仍在，写「—」，不是整张缺失。真实 0 仍是「0.0 秒」。
- 已退出的进程留在榜上，标「已退出」。同一 pid 换了启动时间是另一个进程，不把旧的合计并进去。
- Pulse 自己的行留在榜上，名称写成「Pulse」。
- 缺失的增量跳过，不算 0，也不把已有合计清成 0。缺失指：计数回退、客户端消失、这一项读不出、新客户端的第一拍。真实增量为 0 仍是「0.0 秒」。
- 不进菜单栏、快照或进程表。「GPU 占比」卡片和它的规则不变。

## 开销

每一拍都读，包括前台约 1.5 秒和后台约 3 秒，也包括人正看着内存页、CPU 页或其它页的时候。采样线程对 `IOAccelerator` 做一次匹配，沿子节点最多再走两层，对每个 `AGXDeviceUserClient` 复制 `IOUserClientCreator` 和 `AppUsage`。这是每拍多一次 IOKit 注册表遍历和属性拷贝，不另开线程，不写磁盘，也不打开用户客户端。Intel 机器通常找不到 AGX 客户端，遍历之后得到空列表，占比卡仍是缺失，账本也没有行。换来的是：之后打开 GPU 页时，这一小时的合计已经在。

## 后果

- 人在别的页停留过，再打开 GPU 页，能看到最近 1 小时谁用了 GPU。
- 每一页的采样都多一次注册表读取。占比卡仍不用离开期间的样本做基线。
- 退出 Pulse 之后这张榜是空的，下次要重新累加。

## 不考虑

- 把账本写进本机历史或快照：退出就该清空，也不给历史库加列。
- 放进菜单栏：菜单栏仍不显示 GPU。
- 让「GPU 占比」也在离开期间继续排名：那张卡仍只表示最近一拍，而且只在 GPU 页更新。
