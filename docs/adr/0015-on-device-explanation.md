# ADR-0015：端侧解释只复述本机证据

状态：提议（#197）。不改变 [ADR-0005](0005-manual-public-ip-request.md)：公网 IP 仍只在用户点击后查询，本条不增加出站请求。不改变 [ADR-0001](0001-process-memory-footprint.md) 的内存占用，不改变 [ADR-0003](0003-thermal-state-api.md) 和 [ADR-0007](0007-chip-temperature.md) 对 `IOServiceOpen` 和 SMC 的禁止。症状原因和可安全退出判断仍由现有规则决定。本条是提议，不是当前行为。改为已采纳之前，不要写进 `docs/TECH.md`。

## 背景

进程说明库和六张症状卡已经回答「这个进程是做什么的」，以及为什么慢、热、风扇响、掉电快、磁盘满或不睡眠。说明库给出一句说明、三档可安全退出和一句理由。症状卡最多三个原因，各有依据；对不上时写「看不出原因」。风扇转速读不到。可清除空间读不到时保持缺失，不写成 0。

调研希望用 Foundation Models 把这些证据说得更白话。模型会补进程名、数字和原因。截至 2026 年 9 月，Apple Intelligence 在中国大陆仍不可用。把权重打进安装包会加大体积。把进程信息送到 Private Cloud Compute 或第三方接口，就是一条新的出站路径。

## 决定

- 解释只复述本机已经有的事实：`ProcessGlossary` 的一条（说明、可安全退出、理由），以及症状卡已经算出的原因、依据和附注。用的是同一批读数。模型不是事实来源，不参与诊断。诊断不依赖它。
- 规则原文是底稿。进程说明只含说明库里这一条；库里没有的名字不写说明，也不写判断。症状卡只含规则已经列出的原因和附注，包括「看不出原因」「读不到风扇转速」和「可清除空间读不到」。缺数是「—」，不是 0，也不是「正常」。压力档仍只有「正常」和「偏高」。
- 模型只提供这段底稿的另一种措辞，不另起一套诊断。界面上仍是一段解释。不可用时这段就是规则原文，不多一句，也不少原因。
- 只用系统自带的 Foundation Models，只在设备上跑。不用 Private Cloud Compute，不调用第三方 API，不在应用里附带模型权重。安装包不因此变大。
- 只在 macOS 26 或更高、Apple 芯片、用户打开了 Apple Intelligence、并且系统报告模型可用时，才把底稿交给模型。不按地区名单硬编码，也不为探测地区或模型是否在线而联网。截至 2026 年 9 月，中国大陆仍不可用，这些机器得到规则原文。以后系统模型变为可用，沿用同一条门槛，不必再写 ADR。
- 交给模型的只有这一条说明和这张卡的依据。不附整份进程表、路径、主机名或 IP。不放进采样循环。没有已经算出的说明或症状结果，就不调用。
- 回复必须仍是这段底稿：依据里的名字和数字都在，已经列出的原因和缺数都不丢。多出一个底稿里没有的进程名、数字、原因，或「很高」「危险」这类底稿里没有的判断，整段丢掉，显示规则原文。不逐句删改。
- 模型没有回复、调用失败，或系统说不可用，显示的文字与规则原文相同。进程说明和症状卡仍在，功能不消失。
- 不新增出站请求。不改写 ADR-0005。

## 后果

- 详情里的进程说明和诊断症状卡上的解释，要么是规则原文，要么是没有越出原文的措辞。
- 系统版本不够、不是 Apple 芯片、Apple Intelligence 关闭，或模型不可用（含截至 2026 年 9 月的中国大陆）时，看到的仍是这套说明和症状文字，不是空白，也不是报错。
- 安装包不含模型权重。进程信息不为解释离开本机。
- 提议不是当前行为。改为已采纳之前，`docs/TECH.md` 保持现状。采纳之后再补进程说明、症状卡和冒烟项。

## 不考虑

- Private Cloud Compute，以及任何第三方模型 API。调研里直装版能否使用 Private Cloud Compute 不再追问，因为不用这条路径。
- 把模型权重打进仓库或安装包。
- 让模型自己列原因、改可安全退出的三档，或在缺数时填 0。
- 模型不可用时藏起说明或症状卡。
- 为解释而联网，包括启动时探测、轮询和地区查询。
- 杀毒、恶意软件评分，或按模型给进程下安全结论。
- 用解释去改内存占用、芯片温度或风扇来源。风扇仍不读 SMC。

## 后续实现 ticket

### 1. 由说明库条目和诊断依据写成规则原文

- 阻塞：无
- 交付：不调用模型。一条进程说明和一张症状卡各自得到一段冷静的中文规则原文。原文只复述说明、可安全退出、理由，以及这张卡已经有的原因、依据和附注。没有说明的进程不出说明。缺数是「—」。看不出原因时仍是「看不出原因」。
- 测试接缝：纯函数。抓住原文里的事实都能在说明库条目和已有依据里对上，缺数不会变成 0。放掉模型是否可用、文字放在界面的哪一处、以及有没有出站请求。

### 2. 模型不可用或越出证据时退回规则原文

- 阻塞：第 1 张
- 交付：模型不可用、失败，或回复里有底稿没有的事实时，得到的文字与规则原文逐字相同。只有回复仍对得上底稿里的名字、数字、原因和缺数时，才采用模型措辞。
- 测试接缝：纯策略，配一只假的模型适配器。抓住「不可用」和「越出证据」都得到与规则原文相同的结果，越界时整段退回而不是删一句。放掉 Foundation Models 本身：不加载系统模型，也不在真机上验证 Apple Intelligence。

### 3. 进程说明和症状卡显示这段文字

- 阻塞：第 2 张
- 交付：详情侧栏的进程说明和诊断症状卡显示第 2 张给出的文字。失败或不可用时两处仍是规则原文，功能不消失。说明库里没有的名字仍不显示说明。
- 测试接缝：WiringSourceTests。抓住源码把这两处绑到这段文字，失败路径仍是规则原文，文案保持冷静。放掉真的画出一扇窗口、模型生成的好坏，以及一台 Mac 上 Apple Intelligence 是否开启。

### 4. 解释路径不发起出站请求

- 阻塞：第 2 张
- 交付：能核对解释路径没有新的出站请求。公网 IP 仍只在用户点击后查询。
- 测试接缝：WiringSourceTests。抓住解释相关源码不创建出站会话、不访问第三方地址、也不打开 Private Cloud Compute。放掉运行时抓包。抓包要等本条改为已采纳之后的冒烟，不在这张里。
