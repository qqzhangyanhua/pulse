# ADR-0011：进程下载和上传只在网络页调用 nettop

状态：已采纳（#191）。不改变 [ADR-0004](0004-gpu-accelerator-stats.md) 的 GPU 读数来源，也不放开对 `IOServiceOpen`、Metal 计数器和 `powermetrics` 的禁止。不改变 [ADR-0005](0005-manual-public-ip-request.md)：公网 IP 仍只在点击后查询。主机下行和上行仍走原来的主机计数，不改成 `nettop`。

## 背景

网络页已经有整机下行和上行。进程表上的「网络」列一直写「暂不可用」，因为没有按进程的字节来源。活动监视器这一列来自 `nettop`。把那一列写成 0 会把读不到假装成没有流量。

`nettop` 是本机命令。它要常驻才能给出每秒速率，离开页面以后继续跑会空耗 CPU。

## 决定

- 只执行固定路径 `/usr/bin/nettop`。参数是 `-P -x -c -L 0 -s 1 -n -J bytes_in,bytes_out`。不经过 `/bin/sh`、bash 或 zsh，不拼命令字符串。不用 `-d`：读累计字节，自己做差。`-x` 让字节保持整数。`-J` 的列序不稳定，按表头名认 `bytes_in` 和 `bytes_out`。
- 标准输入是一根一直开着、从不写入的管道，不是 `/dev/null`。读到文件结束会让 `nettop` 空转。
- 只在网络页被选中时启动。离开这一页、视图模型释放、以及应用退出时，先 `SIGTERM`，仍在跑就 `SIGKILL`，然后等子进程结束。冷启动停在内存页，不启动它。不放进 `MemorySampler`。
- 采样间隔约 1 秒，并且只在这一页可见时发生。`-c` 让 `nettop` 少占 CPU。其它页没有这个子进程。
- 第一拍只做基线，不显示速率。某一侧缺失、不是整数、或计数变小，这一侧是「—」，不是 0。真实增量为 0 仍是 `0 字节/秒`。整段表头读不出时保留上一拍已经显示的速率，不换成一排 0。
- 进程行上不存字节字段。「暂不可用」仍留在模型里，表格不再显示它，也不把它当成 0。详情侧栏仍是「当前进程网络暂不可用」，没有进程网络曲线。
- 「下载」「上传」可排序。缺读数在升序和降序都排在最后，同值按 pid 升序。

## 后果

- 网络页进程表用下载和上传代替原来的「暂不可用」列。
- 离开网络页或退出 Pulse 之后，不应该再有这次启动的 `nettop`。
- 不要为了这一列去改主机下行 / 上行，也不要在其它页把 `nettop` 留着跑。
