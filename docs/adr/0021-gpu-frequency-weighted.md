# ADR-0021：GPU 频率按非关闭档的停留加权

状态：已采纳（#221）。取代 [ADR-0012](0012-energy-model-power-frequency.md) 里「GPU 频率在名字只是档位标签时保持「—」、不用频率表」。CPU 簇频率仍沿用 ADR-0012：驻留最多的状态，而且名字本身要写成频率。功耗规则仍是 [ADR-0020](0020-gpu-power-energy-channel.md)。

## 背景

Apple 芯片上 `GPU Stats` 的状态名是 `OFF`、`P1`…`P15` 这样的档位标签，不是赫兹。ADR-0012 只解析写着频率的名字，所以 GPU 频率一直是「—」。只取驻留最久的一档也会丢掉这一间隔里其它档的时间。

pmgr 注册表的 `voltage-states9` 是小端的 Hz、mV 成对 uint32。第 0 项是 OFF。MacBookPro18,3（M1 Pro，14 核 GPU）、macOS 26.6.2 上，这一表是 OFF，加上 389、486、648、778、972、1296 MHz。其它代芯片是不是也用这个键，还没有核实。

## 决定

- 只读 `GPU Stats` 组里的 `GPU Performance States` 子组。其它子组不参与 GPU 频率。
- 频率表只读名为 `pmgr` 的注册表条目上的 `voltage-states9`。不调用 `IOServiceOpen`。字节解析放在可移植代码里：空字节或长度不是 8 的倍数时，表是 nil。
- `Pn` 映射到表的第 n 项。第 0 项是 OFF，不把它的赫兹当成工作频率。
- GPU 频率是这一间隔里非 OFF 档按停留时间加权的平均。OFF 的停留不计入分子或分母。
- 整个间隔都是 OFF（有 OFF 停留，且没有工作档停留）时显示「空闲」。这不是 0，也不是「—」。不需要频率表也能判断关闭。
- 表读不到、标签对不上（不是 OFF，也不是落在表内的 `Pn`），或还没有样本差时，显示「—」。不猜一个数，也不写成 0。
- CPU 簇频率不变。
- 不进曲线、本机历史、菜单栏、快照或进程表。

## 后果

- 档位标签能显示成 GHz。M1 Pro 上工作档落在 0.39 GHz 到 1.30 GHz 这一段，而不是一直「—」。
- 整个间隔关闭时，频率行和读屏文案是「空闲」，避免把关机看成 0 GHz 或读不到。
- 频率表对不上的机器仍是「—」。

## 已知限制

其它代芯片是否用同一个 `voltage-states9` 键尚未核实。读不到表时保持「—」，不用另一份表或最高档代替。

## 不考虑

- 用驻留最久的一档代替加权平均：短时间冲到高档会被抹掉。
- 把 OFF 当成 0 Hz 算进平均：会把空闲拉低成一个假频率。
- 表缺失时套用 M1 Pro 的六档：会在没核实的芯片上造数。
