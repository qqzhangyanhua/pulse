# ADR-0010：本机历史只保存已经采到的主机读数

状态：已采纳（#194）。不改变 [ADR-0008](0008-gpu-history-keeps-recording.md)：实时曲线仍在每一页记录，离开不删，也不改成这只数据库。不保存芯片温度、功耗、频率，也不保存能耗页那条 4 小时进程合计。

## 背景

实时曲线大约只有两分钟，关了 Pulse 就没了。诊断要回看更久的已用内存、压力、整机 CPU、网络、磁盘和 GPU 使用率，以及中间机器睡过、热过、压力变过没有。把没采到的分钟填成 0，会把关机看成空闲。

这些读数留在这台 Mac 上。进程名在里面，不上传。

## 决定

- 默认开启。库文件是 `~/Library/Application Support/com.qqzhangyanhua.pulse/history.sqlite`。只用系统自带的 SQLite C 接口。
- 分层在 `HistoryPolicy`。原始样本保留 1 小时。1 分钟一档保留 7 天。15 分钟一档保留 90 天。超过保留期的丢掉。某一档里没有样本就是缺口，不是 0。
- 存储不做这些判断。它只写下策略已经算好的样本、前 10 名和事件，并按策略给出的时间删掉更早的原始样本。
- 每一拍成功才写。写的是这一拍的已用内存、压力、交换、整机 CPU、网络上下行、磁盘读写和 GPU 使用率。这一拍没有读到 GPU，就记缺失，不沿用画面上还显示着的上一个百分比。
- 每一拍另写 CPU 有读数的前 10 个进程。没有 CPU 读数的不进这 10 个，也不当成 0。真实 0 仍在。
- 事件单独记：睡眠、唤醒、热状态变化、压力档变化。热状态用 `nominal`、`fair`、`serious`、`critical`、`unknown`，不从降频那句话反推。睡眠和唤醒由存储自己听系统通知。
- 可以清空。清空之后，实时曲线还在，更久的范围是空的，不是一串 0。

## 后果

- 实时曲线的规则不变。历史是另外一份、留得更久的本机读数。
- 没打开 Pulse 的时候没有新样本。再打开时，中间是缺口。
- 不要把芯片温度、功耗或频率补进这一版的表里。
