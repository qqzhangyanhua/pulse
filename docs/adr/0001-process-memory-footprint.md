# ADR-0001：进程内存按内存占用（footprint）显示

状态：已采纳（二十八期，#88）。取代十七期的驻留内存口径。

## 背景

一期到二十七期，进程「内存」列和详情用的是 `proc_pidinfo` 的 `pti_resident_size`（驻留内存）。十七期把这个口径写进了详情标题（「驻留内存」）。

驻留内存会把共享页算进来，又不计被压缩的部分，和活动监视器的「内存」列口径不同。用户拿两边对照时，同一个 App 的数字差距很大，排序也不同。

## 决定

- 进程内存使用 `proc_pid_rusage`（`rusage_info_v4`） 的 `ri_phys_footprint`（内存占用）。这次 rusage 读取同时提供磁盘计数，不增加系统调用。
- footprint 读成功就用，真实 0 也算有效读数。只有 rusage 读取失败时才回退到 `pti_resident_size`，并在行上记录 `memorySource = .resident`。
- 内存页详情标题写「内存占用」。回退行写「驻留内存」，占比句写「按驻留内存计算」；按 App 合并时，只要有成员回退，就写「部分按驻留内存计算」。
- 上涨信号、Top5 序列、菜单栏 Top3、排序都使用同一个 `memoryBytes`，不另开一套口径。

## 后果

- 数字和排序跟活动监视器一致，用户对照时不再困惑。
- 回退行和正常行在同一列里排序，数值口径不完全相同。界面通过「驻留内存」标注说明这一点，不把回退行藏起来。
- 二十八期之前设计稿里关于「驻留内存」的措辞已经过时，归档文件开头已注明。
