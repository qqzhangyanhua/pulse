## 锁定的可见行为

只改内存页详情里三处说明：内存大数旁边、内存主曲线、内存趋势。说明跟随这一帧实际画出来的对象。代表 pid 换人、过滤让 N 变化时，句子跟着变。本期只把已经存在的回退标出来，不改选中、不重选、不修曲线连续。

共享的 `ProcessDetailSidebar` 继续给各页用。下面的新句子只在 `DashboardPage.memory` 产生。其它页调用同一函数时得到空，界面不出现这些句子。

### 大数旁边

大数仍是现在画出来的那个字节数，不另算一遍。

内存页上，`displayedMemoryRow` 已经决定大数用哪一行：开关打开、当前页允许合并、并且 `sortedRows` 里还有这个 pid 时，用合并行；否则用采样器里的那一行。归属句只看这一行，不看「按 App」开关本身。

- 这一行的 `groupedMemberCount` 有值：紧邻大数写「当前可见的 N 个同名进程合计」。N 就是这个计数值，包括 1。它和字节数来自同一次 `combine`。
- 这个字段为空：写「当前进程（PID 123）」。123 是这一行自己的 pid。打开了合并、但代表 pid 已经换掉、查找未命中时，走这一句，不写成合计。
- 未合并的行本来就是空计数值，也走进程句。

禁止出现的说法：整个 App、全部成员、完整 App 内存，以及把这句说成 App 的内存。不写「按 App 已打开所以这是合计」。

占比句保持 `MemoryDetailPresentation.field` 的现有结果，而且只描述大数那一行。组合计命中且有成员回退时，大数仍写「部分按驻留内存计算」。归属句不代替占比句，也不把占比句拼进归属句。

### 内存主曲线

曲线点列仍是选中 pid 的 `memorySeries`。不新建组历史。

曲线的口径标题只用这条曲线所属进程自己的 `memorySource`：

- `.footprint`：标题「内存占用」。
- `.resident`：标题「驻留内存」。

不读取合并行的 `memorySource`，也不读取 `residentMemoryIsPartial`。组里别人回退、当前进程仍是内存占用时，大数可以写「部分按驻留内存计算」，曲线标题仍是「内存占用」。两边各说各的。不为了让两边措辞相同去改采样或改回退规则。

点数不少于 2 时，摘要写成「PID 123 · 最近 … · 峰值 …」。最近和峰值仍用现有的序列末点与最大值，格式仍是 `ByteFormat.memory`。123 是曲线所属进程的 pid，不是合并行的成员数。

点数是 0 或 1 时，占位仍是「正在采集内存曲线」，摘要仍空。这个状态不写 PID。没有选中、侧栏没有详情时，不画这条曲线，也不补一个 PID。

### 内存趋势

上涨判断的输入、80 点、8 MiB 和 60% 间隔都不变。`.none` 仍然不占位。没有选中时槽位仍是空，不编一条趋势，也不编一个 PID。

只有上涨槽在现有标题、说明和旁注之外，同一组读屏文字里再加一句「这条趋势属于 PID 123」。123 是曲线所属进程的 pid。上涨已经至少有 80 个点，这句话不制造历史。样本不足保持「样本不足，暂不判断」，不追加 PID，也不改成上涨。没有历史时不编 PID。

`MemoryGrowthCopy.basis` 继续是「当前进程近期趋势 · 基于现有内存占用」，只在上涨时出现。不足和 `.none` 的旁注仍是空。不把这句改成 App 趋势，也不把 PID 塞进这个常量。

### 一句对照

| 实际画出来的对象 | 大数旁边 | 曲线标题 | 点数 ≥ 2 的摘要 | 趋势槽 |
| --- | --- | --- | --- | --- |
| 合并行，N 个可见同名进程 | 当前可见的 N 个同名进程合计 | 曲线所属进程自己的口径 | PID 加最近、峰值 | 仅上涨槽写「这条趋势属于 PID …」 |

## 和当前源码的接法

这些路径在 `cf84c4d` 上已经存在，约定只改展示：

- 大数行：`ProcessDetailSidebar.displayedMemoryRow`。命中时 `sortedRows` 里的合并行带 `groupedMemberCount`；未命中时 `?? row` 回到采样器行，该字段为 `nil`。
- 曲线点：`ProcessDetail.memorySeries`，由 `MemorySampler.detailFrame` 按选中 pid 追加。
- 大数口径：`MemoryDetailPresentation.field`，继续接收大数那一行的 `memorySource` 和 `residentMemoryIsPartial`。
- 趋势槽：`MemoryGrowthSidebar.slot`。空选中返回空；有选中但序列空，结果是样本不足，不是上一个进程的上涨。

建议新的纯展示类型放在 `Pulse/Models/`，例如 `MemoryDetailAttribution`。输入是页、大数行、曲线行、内存点数、趋势是不是上涨。内存页以外返回空。不要把 `groupedByApp` 传进去。上涨与否由调用方用已经算好的槽位说明传入，模型里不调用 `evaluate`。

曲线行必须是采样器的 `detail.row`，不要传 `displayedMemoryRow` 的结果。大数行才用 `displayedMemoryRow`。

`memoryChart` 今天用 `memoryField(displayedMemoryRow(detail.row)).title`，所以主曲线标题会借合并行的口径。这是要拆开的展示点，不是要改的数据源。拆开只放在 `selectedPage == .memory` 的分支：内存页改用曲线行的 `memorySource` 取标题。CPU、网络、磁盘、本机和 GPU 仍走原来的 `memoryField(displayedMemoryRow)`，标题继续是「内存」。

归属句是可见 `Text`。大数那句放在内存大数卡片里、占比句下面，不写进占比 caption 字符串，也不只用 `.help`。`.help` 是指针提示，不能代替可见文字。`SidebarMetric` 若增加可选归属参数，默认必须是空；只有内存页那张内存卡传入。CPU 卡和其它页的内存卡不传。

趋势那句只在上涨时放进现有的 `memoryTrend`，并留在同一个 `accessibilityElement(children: .combine)` 里。样本不足不加这句。不另设一个和可见文字不同的 `accessibilityLabel`。可见文字里不出现「App 趋势」。

冻结缺席卡和未选中空态不画这三句。`showsLiveTrend == false` 时趋势槽不出现，趋势 PID 句也不出现。

## 曲线历史的限度

`ChartSample` 只有 `id`、`date`、`value`。内存点是当时的 `memoryBytes`，点上没有 footprint / 驻留标记。

因此曲线标题只能说明这个进程当前这一行的口径，不能证明每一个历史点都是同一种口径。进程中途从内存占用变成驻留内存，或反过来，旧点仍留在同一条环里。标题会跟着当前行变，旧点不会被标出来，也不会被改写。

环的键只有 pid。进程退出并让选中变空时，现有逻辑会清空环。若同一个 pid 数值在选中没变的情况下被系统复用，新字节会接在旧点后面。归属句写的是当前选中 pid，不能证明每个点都属于同一次进程生命。本期不给 `ChartSample` 加来源或启动时间，也不为了这句话去切断环。

前 5 名序列和选中环在 pid 位于前 5 时共用，仍然是这个 pid 的字节，不是同名进程的合计。

## 测试

纯模型和源码接线用 `swift test` 验收。这些测试不打开窗口，不代替 macOS 上的界面点击，也不代替 VoiceOver。落地 PR 若要报本机冒烟，须另列人跑过的项和跳过的项。本文档 PR 没有跑冒烟。

纯模型要覆盖，并且现有占比、回退和上涨阈值测试保持原断言：

- 合并命中：N 来自该行 `groupedMemberCount`，句子等于「当前可见的 N 个同名进程合计」。N 为 1 也用这句。
- 未命中回退：计数值为空，即使调用者知道开关开着，句子仍是「当前进程（PID …）」，pid 是大数行自己的。
- 非合并：同样是进程句。
- 过滤使 N 从 3 变成 1：两次调用各写各的 N，不保留旧 N。
- 代表变化：用「计数值为空的当前行」表示未命中，句子回到该 pid，不出现合计。
- 来源不同：大数行是驻留且 `residentMemoryIsPartial`，曲线行是内存占用。大数占比仍由 `field` 写出「部分按驻留内存计算」；曲线标题是「内存占用」，曲线句子不含「部分按驻留」。
- 曲线行自己是驻留：曲线标题是「驻留内存」，仍不写「部分」。
- 无历史：点数 0 和 1 时曲线 PID 句为空，占位常量仍是「正在采集内存曲线」。点数不少于 2 时摘要带曲线行的 pid。
- 无趋势槽、样本不足、非内存页：不写「这条趋势属于 PID …」。只有上涨槽才写，pid 取曲线行。
- 新句子不含「整个 App」「全部成员」「完整 App」「App 趋势」。
- 模型不调用 `MemoryGrowthSignal.evaluate`，不读取采样器。

接线测试只读源码文本，证明内存页分支写了这些句子，CPU 详情函数体没有这些句子，曲线标题在内存页改用曲线行，趋势 PID 句在合并读屏元素内，且没有第二套 `accessibilityLabel`。`MemoryGrowthCopy.basis` 的字面量测试保持不变。`memoryChart` 里现有的「标题来自 `displayedMemoryRow`」断言要改成内存页分支的新断言；这是落地 PR 的事，不是把旧接线假装成新行为。
