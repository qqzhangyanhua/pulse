# Pulse 技术设计（当前实现）

这份文档描述 `main` 上**现在**的实现。行为或口径改了，就在同一个 PR 里改这里对应的段落，不要在文末追加新的一期。

每一期落地前的设计稿归档在 [docs/specs/](specs/README.md)，只作历史参考，不作为决策依据。跨期的口径决定记在 [docs/adr/](adr/)。信息冲突时以代码为准，其次是 ADR、本文档和 PRD，最后才是归档稿。发现本文档和代码不一致，就在同一个 PR 里改本文档。

## 总体约束

- macOS 14+，SwiftUI 原生，单 Target、单进程。不拆 Helper / XPC，不装内核扩展。
- 非沙盒，`Pulse.entitlements` 为空 dict，Hardened Runtime 打开，公证直装（见 [RELEASE.md](RELEASE.md)）。
- 读不到就显示「—」「暂时读不到」「未采样」，**不写假 0**。真实 0 照常显示。
- 文案冷静：压力只有「正常 / 偏高」，不出现「危险 / 危急 / 泄漏」。菜单栏和界面都不用警报红。
- 可移植逻辑（Darwin / AppKit 无关）放进 `Package.swift` 的 `SamplingCore` 源列表，由 `swift test` 覆盖。

## 架构

```
PulseApp ─┬─ ContentView / MemoryDashboardView ── Views/*
          └─ PulseAppDelegate ── MenuBarController（NSStatusItem + NSPopover）
                 └─ MemoryDashboardVM（@MainActor，唯一 VM，活过窗口）
                 │ 采样循环：SamplingRequestGate + SamplingClock + SamplingSession
                 ▼
             MemorySampler（actor，唯一采样器）
                 ├─ HostMemoryReader / SwapUsageReader / PressureProvider / KernelPressure
                 ├─ HostCPUReader（整机 + 每核）
                 ├─ HostNetworkReader / HostDiskReader
                 └─ ProcessEnumerator（proc_listpids / proc_pidinfo / proc_pid_rusage）
             HostMachineReader（只给本机页，不在采样器里）
```

- `MemorySampler.sample()` 每次产出一帧不可变的 `SampledFrame`：主机内存快照、进程行、选中进程详情、整机 CPU、最忙一核、主机网络 / 磁盘速率、Top5 内存序列、权限脚注。主线程只读这帧。
- 主窗、菜单栏、各资源页都读同一个 VM 的同一帧。没有第二个采样器，也没有第二条轮询。这个 VM 归 `PulseAppDelegate`，启动完成就 `start()`，关窗不释放。
- `Models/` 里的类型是纯投影：输入现有字段，输出文案和状态，不采样、不存历史。
- 「保存当前快照」不新增采样器。它在主线程抄下已经发布的那一帧，做成预览和本机 HTML。

## 采样节奏与失败

- 前台（主窗可见且 App 激活）每 1.5 秒采一帧；主窗在后台或已关、只剩菜单栏时每 3 秒一帧（`SamplingPace`）。循环每 400ms 醒一次，只为及时察觉前后台切换，到期才采。
- 采样在 `applicationDidFinishLaunching` 开始，不等主窗出现。没有主窗时采样门保持窗口不可见，走后台 3 秒。带着主窗启动时，窗口锚点把采样门改回前台，第一段间隔仍是 1.5 秒。`start()` 幂等，窗口再次绑定不会开第二条循环。
- 关掉主窗不退出 App（`terminateAfterLastWindowClosed = false`），菜单栏继续用同一个采样器。`⌘Q` 才真正退出。
- 采样失败进入失败空态，保留上一帧的数据和曲线，不清零。七处失败空态共用 `SamplingRetryChrome`：按钮「重试」，等待中显示「正在重试…」。
- 手动重试和定时到期共享同一个在途请求（`SamplingRequestGate`）。在途时再点重试会并入当前请求，不会再排一帧。重试期间不会把「失败」退回「采样中」。

## 主机读数

| 读数 | 来源 | 缺失时 |
| --- | --- | --- |
| 已用 / 总量 / 分类条（App、联动、被压缩、已缓存） | `host_statistics64` + 页大小，按活动监视器的分类映射 | 整帧失败 |
| 压力档 | `kern.memorystatus_vm_pressure_level`：1 为正常，2 和 4 为偏高。读不到或未知值（含 0、3）不硬判，回退启发式（已用 ≥ 88% 或压缩 ≥ 18% 为偏高）。仍只有两档 | — |
| 交换已用 | `vm.swapusage`，返回长度必须一致 | 「— / 未采样」，不算整帧失败 |
| 整机 CPU | `host_statistics(HOST_CPU_LOAD_INFO)`，两帧求差 | 第一帧「—」 |
| 最忙一核 | `host_processor_info`，两帧求差取最大 | 「—」 |
| 网络上行 / 下行 | `sysctl` `NET_RT_IFLIST2` 的 64 位 `if_data64` 计数，两帧求差。`getifaddrs` 的 `ifi_ibytes` / `ifi_obytes` 是 32 位，每 4 GiB 回绕，不再使用 | 「—」 |
| 磁盘读取 / 写入 | IOKit `IOBlockStorageDriver` Statistics，两帧求差 | 「—」 |
| 降频 | `ProcessInfo.thermalState`，`serious` / `critical` 时显示「系统正在降频以控制温度」 | 不显示 |

降频句出现在内存、CPU、网络、磁盘、本机各页的总览里，菜单栏不读。

## 进程读数

- 进程列表来自 `proc_listpids`，每个 pid 读 `proc_pidinfo(PROC_PIDTASKINFO)` 和一次 `proc_pid_rusage`。任务信息失败且 errno 为 EPERM 的进程不进表。这一帧这种失败的次数 N > 0 时，进程表底部写「另有 N 个系统进程没有读取权限」。ESRCH 不算，N 不跨帧累计，N 为 0 不写这句话。列表整个读失败时 `processListFailed = true`，表进失败空态，不写这句脚注，也不写 0。缺数仍是「—」。
- CPU%：`proc_pidinfo` 的用户态和内核态是 Mach 绝对时间 tick。每帧读一次 Mach 时间基，换成纳秒后再做两帧求差。时间基读失败或换算缺失时这一帧是「—」，不把原始 tick 送进速率，也不写成 0。第一帧、新出现的进程、计数变小仍是「—」。多核可以超过 100%。整机 CPU 和最忙一核仍用 `host_statistics` 的 tick，不经过这次换算。排序用换算后的百分比。
- 磁盘读取 / 写入：`proc_pid_rusage` 的累计字节两帧求差。读失败的进程显示「—」。
- 能耗影响 / 唤醒：同一次 `proc_pid_rusage`（`rusage_info_v6`）的 `ri_energy_nj`（纳焦）和 `ri_interrupt_wkups`，两帧求差。瓦特 = 纳焦差 / 秒 / 1e9，唤醒 = 次数差 / 秒。第一帧、计数变小、读取失败都是「—」。没有替代来源。v6 失败不另读 v4：内存仍回退驻留内存，能耗和唤醒缺失。见 [ADR-0002](adr/0002-process-energy-wakeups.md)。列名不表示活动监视器的能耗影响分数。
- 网络：没有按进程的数据来源。网络页的进程列写「暂不可用」，悬停说明「没有进程速率。主机下行和上行在总览。」。

### 内存口径

见 [ADR-0001](adr/0001-process-memory-footprint.md)。

- 进程「内存」= `ri_phys_footprint`（内存占用，和活动监视器的「内存」列一致）。真实 0 也算有效读数。
- 只有 `proc_pid_rusage` 读失败时才回退到 `pti_resident_size`（驻留内存），这一行带 `memorySource = .resident`（`ProcessMemoryChoice`）。
- 内存页详情（当前界面）：大数标题按大数那一行写「内存占用」，回退行写「驻留内存」。有总量时占比句是「占物理内存的 X%（按内存占用计算）」，回退行写「按驻留内存计算」；按 App 合并后只要有一个成员是回退，就写「部分按驻留内存计算」。没有总量时只写「占物理内存」，旁边加一句静态说明，不显示占比。占比句只描述大数那一行。大数下面另写归属：这一行 `groupedMemberCount` 有值时写「当前可见的 N 个同名进程合计」，N 含 1；计数值为空时写「当前进程（PID …）」，合并未命中也走这一句。主曲线标题用曲线所属进程自己的口径，「内存占用」或「驻留内存」，不借合并行，也不读「部分按驻留」。点数不少于 2 时摘要是「PID … · 最近 … · 峰值 …」；0 点或 1 点仍是「正在采集内存曲线」，摘要为空，不写 PID。CPU 辅曲线不写 PID。内存页且「按 App」生效时，大数先确认选中 pid 还在这一帧未合并的可见行里，再用该行当前名称匹配可见同名组合计。字节、占比、口径和 N 都来自这一合并行，N 含 1。选中 pid 不在可见行里时不借其它同名进程，退回该 pid 自己。CPU 页和其它页仍用 `displayedMemoryRow` 的 pid 查找。
- 其它页的详情标题仍是「内存」，不区分口径。

## 页面

`DashboardPage`：内存、CPU、磁盘、网络、本机可选。GPU 留在枚举里但不可选，Tab 栏直接不显示它（`ResourceTabs` 只画可选的页）。冷启动在内存页。主窗用 frame autosave 记住尺寸和位置，不记页面、排序和过滤。

快捷键（「视图」菜单）：`⌘1`–`⌘5` 切到内存 / CPU / 磁盘 / 网络 / 本机，`⌘F` 聚焦名称过滤，`⌘⌫` 对选中进程做普通退出（过滤框有焦点时不注册，本机页禁用）。`⌘C` 复制选中进程行；过滤框有焦点时仍复制文字。没有选中行，或当前是本机页，不改剪贴板。强制退出和 GPU 没有快捷键。

### 内存页

- 总览：紧凑双行布局。第一行用量大数与历史曲线、分类构成条（按类型与图例）；第二行四格（内嵌趋势的压力档、可用、交换、占用最多的 App），降低纵向高度并扩充进程表可视区域。
- 进程表：名称、CPU、内存、线程，默认内存降序。表头可点排序，同值按 pid 升序。选中行可用 ⌘C 或右键「复制」，写成一行制表符分隔文本：名称、PID（按 App 合并时写成员数，含只有一个成员的组）、这一页表格里的读数。缺数是「—」；网络列仍是「暂不可用」。CPU 页带上能耗影响和唤醒，磁盘、网络页同一规则，列跟各页表格走。当前行高亮仍是 `selectedPid == row.pid`：底色和 `ProcessLine` 的文字颜色用同一次比较。列表的 `selection` 绑定也是这个 pid。
- 内存页当前选中进程所在可见同名组的行高亮：已锁定，尚未改界面。它只表示这一行包含原来的选中进程，不是稳定组选择，也不是整组操作。落地前以上一条为准。约定见 [specs/34-memory-group-row-highlight.md](specs/34-memory-group-row-highlight.md)。CPU 页仍用 pid 比较。滚动、`⌘C` 和右键复制不在这项里。
- 工具栏胶囊开关，默认都关，只在本次会话内有效：
  - 「仅上涨」：只留下有「上涨」徽标的行。只在内存页。
  - 「仅窗口 App」：只留下 `activationPolicy == .regular` 的进程。只在内存页。开关关闭或不在内存页时不查询哪些进程有窗口；打开且在内存页时，可见行和选中回落各查一次。
  - 「按 App」：内存页和 CPU 页都有。把当前可见行按名称合成一行，内存、线程、CPU、磁盘相加，任何成员缺数则合计缺数。能耗和唤醒按有读数的成员相加，有成员缺失则保留部分和并在详情注明「部分读数」，全部缺失仍是「—」。选中落到该组内存最多的 pid。磁盘页和网络页不合并。
- 过滤顺序：名称过滤 → 仅上涨 → 仅窗口 App → 按 App 合并 → 表头排序。菜单栏 Top3、上涨 Top5 和「占用最多的 App」都读未过滤、未合并的完整列表。
- 过滤后无结果：「清空过滤」一次清掉名称、仅上涨和仅窗口 App，「按 App」保持不变（`clearMemoryPageFilters`）。只开「仅窗口 App」导致的空态也走「没有匹配的 App」，副句仍是「清空名称和仅上涨过滤。」，没有提到仅窗口 App。采样中、列表失败、无进程这几种空态优先。
- 「占用最多的 App」卡可点：确认 pid 还在列表且名称没变，必要时把名称过滤改成该名称，关掉「仅上涨」和「仅窗口 App」（「按 App」不变），然后选中并滚到该行（`TopAppLocation`）。

### 上涨信号

- 窗口是选中进程或 Top5 进程自己的内存序列，最多 90 点（`ChartSampleRing`）。
- 不足 80 点：详情写「样本不足，暂不判断」，列表不显示。
- 满 80 点后，首尾净增超过 8 MiB **且**至少 60% 的相邻间隔上涨，才算上涨；中间可以有下降。不做斜率拟合，不判泄漏。
- 详情（当前界面）：「内存趋势 · 近期内存占用上涨」，旁注「当前进程近期趋势 · 基于现有内存占用」，上涨时同一组读屏文字里再加「这条趋势属于 PID …」。样本不足仍是「样本不足，暂不判断」，不追加 PID。没有上涨时不占位。旁注不改成 App 趋势，也不把 PID 写进旁注常量。下面有默认收起的「采样窗口与判断依据」。
- 列表：只有当前内存页排序下完整列表的前 5 个进程有序列（`MemoryGrowthTopSeries`），满足条件时显示「上涨」徽标。掉出前 5 的 pid 当轮丢弃序列。切到其它页时，Top5 仍按最后一次内存页排序算。

### CPU / 网络 / 磁盘页

- CPU 页：总览整机 CPU 与历史曲线、「最忙的一核」；表默认 CPU 降序。进程表另有「能耗影响」（瓦特）和「唤醒」（次/秒），可分别排序，缺数按低于 0 处理。详情显示同样两项；按 App 合并时这两项用成员之和，有成员缺失时注明「部分读数」。工具栏有「按 App」，磁盘页和网络页没有。
- 网络页：总览主机下行 / 上行与曲线；进程网络列「暂不可用」；表默认 CPU 降序。
- 磁盘页：总览主机读取 / 写入与曲线；「读取」「写入」两列可分别排序，缺数的行按低于 0 处理（降序时排在最后）；默认按读写合计降序。
- 详情侧栏按当前页呈现主读数（`ResourceDetailPageProjection`）。
- 总览曲线在当前值缺失时附「历史曲线 · 当前值暂不可用」（`HistoryCurvePresentation`）。
- CPU / 网络 / 磁盘页名称过滤无结果时，「清空过滤」只清名称。

### 本机页

- 进入时读一次 `HostMachineReader`，停留期间每 30 秒刷新，离开即停。不在采样循环里。
- 身份区：机型（`hw.model`）、芯片、系统版本、核数与内存容量。
- 卡片：CPU（含「较上次」差值和曲线）、内存、磁盘已用（根卷）、电源（电量 / 电源类型 / 低电量模式）、已开机（含绝对开机时间）、交换。有内置电池时，电源区另显示循环次数、健康度（满充容量 / 设计容量）和功率（放电为负）；没有内置电池不显示这一区，单项读不到只该项为「—」。电池来自 `AppleSmartBattery`，跟本机页同一次读取，不进采样循环。CPU、内存和交换直接用采样器的现有数据。
- 诊断三行：内存压力、磁盘空间（已用 ≥ 90% 为偏高）、CPU 负载（≥ 80% 为偏高）。能点的行跳到对应页。
- 没有进程表和过滤，退出命令禁用。

### 详情侧栏与退出

- 选中一行打开侧栏：图标、名称、内存 / CPU 大数、内存主曲线、CPU 辅曲线。切进程时两条曲线清空重采。常见系统进程附一句本地说明（`ProcessGlossary`），表里没有的名字不显示。
- 有应用对象的进程，包括登录窗口、程序坞、访达：「退出」走 `NSRunningApplication.terminate()`，等待最多 2.5 秒。失败后显示「强制退出」，先弹系统 `NSAlert` 确认，再 `forceTerminate()`。这条路径不发信号。
- 没有应用对象时，在 `ProcessActions` 里用 `proc_pidpath` 读可执行路径。路径缺失，或路径等于 `/System`、`/usr/libexec`、`/usr/sbin`、`/sbin`，或以这些前缀加 `/` 开头：不发信号。进程还在则请求失败，已经不在则未找到。其余普通退出发 SIGTERM，不另加确认；强制退出仍先弹原来的确认框，确认后发 SIGKILL，取消不发信号。
- 信号发出后仍用原来的等待、超时和退出记录（普通 2.5 秒，强制 2 秒）。`kill` 返回 ESRCH 视为未找到，其它失败视为请求失败。侧栏失败文案仍是「未能退出。可以请系统立即结束该进程。」和「系统未能结束该进程。」不按 uid 再拒绝，按钮可点规则不变。
- 退出结果按 pid 记在会话内（`ProcessQuitOutcome`）。进程消失后侧栏冻结在最后一帧，失败卡留在原处可重试。冻结卡的占比分母用消失前最后一次有效总量（`LastLiveTotalReducer`）。
- 退出成功、进程从列表消失后，在第 3 个成功采样点比较整机已用内存：减少达到 50 MiB 写「已用内存约减少 X」，否则写「已用内存变化不明显」。基准缺失、中途失败或切走时不显示。

## 保存当前快照

工具栏有单独的「保存当前快照」，各页都在，包括本机页。它不在过滤胶囊那一组里，也不跟随「仅上涨」「仅窗口 App」「按 App」。

点击时在主线程同步冻结最近一帧已经发布的有效采样：`snapshot != nil` 的那份主机快照，以及同一次发布里的 `rows`、整机 CPU、最忙一核、网络和磁盘。不调用采样器，不读本机页事实，不读降频提示，不读曲线。`samplingFailed == true` 时仍冻结上一份，采样时间保持 `snapshot.capturedAt`。没有有效帧时只提示「暂无可保存的采样，请稍后重试」，不打开预览，不写文件。

`savedAt` 是点击冻结的时刻，界面写「快照生成时间」。预览停留、系统保存面板、同帧重试和写盘都不另取时钟。预览和文件用同一份 `SnapshotDocument`：采样时间、快照生成时间、一句「非实时」、主机内存（已用、总量、App / 联动 / 被压缩 / 已缓存、交换）、压力两档、整机 CPU、最忙一核、网络下行 / 上行、磁盘读取 / 写入，以及未过滤完整进程列表按内存占用降序、同内存再按 pid 升序的前 5 行。不是当前表头排序，不是过滤后的表，也不是按 App 合并后的行。不足 5 个时写「当前只有 N 个进程。」列表没读到时写「进程列表没有读到。」，不把空表说成 0 个进程。名次只表示内存占用顺序。

每一行只有 pid、显示名、内存、内存来源（内存占用或驻留内存）、CPU%、线程数。不写路径、包标识、命令行、曲线、进程磁盘、能耗或唤醒。主窗其它位置的缺数仍是「—」。这份文档里缺失写「不可用」，真实 0 仍是「0 字节」「0.0%」或「0 字节/秒」。非有限浮点在做成文档前视为缺失。可见时间用调用方传入的日历和时区，格式 `yyyy-MM-dd HH:mm:ss`。

「隐藏进程名」默认关。打开后预览和将要写入的文件立刻把名称换成「已隐藏」，冻结值里的原名不改。文件是自包含的 UTF-8 HTML，扩展名 `.html`，`<title>` 固定为「Pulse 采样」。采样文本先转义再进正文；不写脚本、事件属性或链接。默认文件名是 `Pulse-快照-yyyyMMdd-HHmmss.html`，用的是 `savedAt`，不含进程名。

「保存到本机」才打开系统保存面板，不关闭系统自带的替换确认。这一次面板绑在打开它的那份预览上；同一份预览上一次面板还没结束时不再开第二个。回调如果碰到已经关闭或换成另一份预览，不写文件，也不改那份新预览的状态。同一次预览里取消面板不写文件。确认时写入的是当时的隐名版本，只有写入成功才显示「已保存」。取消预览，或取消保存面板，都不写文件；取消面板后预览还在。写入先落在目标同一目录的临时文件，再替换到目标。失败时目标原有字节保持不变，预览留着同一份冻结，提示「没能写入所选位置。这一份采样还在，可以再试。」只有替换成功才显示「已保存」。保存成功后如果「隐藏进程名」的实际开关变了，「已保存」撤掉，改为「隐藏进程名已改变。当前预览还没写入文件，请重新保存。」取消保存面板或再次写入失败都不会把这份新预览说成已保存；开关设成当前值则不撤。冻结的采样、采样时间、快照生成时间和默认文件名都不变，原来的文件要等下一次写入成功才替换。应用不打开这个文件。回看是用户稍后用系统打开那份本地 HTML。没有应用内导入、历史列表或历史 PID 操作。

## 菜单栏

- 状态项画一个压力色点：正常为冷静绿，偏高为琥珀，无数据或失败为灰，并附提示「暂时读不到」。默认栏上没有文字。设置里可选「仅色点」「色点 + 已用内存」「色点 + CPU」，默认仅色点；后两种在色点旁显示对应读数，缺失为「—」，数字等宽。选择存在 UserDefaults，重启后保留。`⌘,` 或轻量条里的「设置」打开设置窗口。
- 压力升到偏高时发一条系统通知，默认开，设置里可关。同一轮偏高只发一次；连续正常满 5 分钟后才重新可发。缺帧或采样失败不发，也不重置这一轮。文案是「内存压力偏高，可以看看谁占得最多」，有占用最多的 App 时带上名字。点击走「打开 Pulse」的同一条路径，打开主窗内存页。系统拒绝通知权限时不弹错误，设置里显示「系统通知未授权」。
- 左键弹出轻量条，右键或 Control 点击弹出「退出 Pulse」。
- 轻量条自上而下：压力一行、「已用 xx GB」一行、最忙一核达到 90% 时的「最忙的一核 · xx%」（可选），然后是 Top3 进程（名称 + 内存），最后是「打开 Pulse」和「设置」。
- Top3 用最后一次内存页表头排序，取完整列表的前 3 个，不受过滤影响。少于 3 个时不补位。
- 点 Top3 某行：关掉轻量条，进程还在才选中，打开主窗并切到内存页。切页时会按内存页当前的「仅上涨」「仅窗口 App」重算选中，被开关过滤掉的进程会被取消选中。「打开 Pulse」只切到内存页，不改选中。没有主窗时，「打开 Pulse」和通知点击仍走这条路径打开主窗。

## 设置

- 「登录时打开 Pulse」的开关每次从 `SMAppService.mainApp.status` 读取，不另存布尔值。只有已启用为开；未注册为关。Pulse 启动时不会自己注册。打开调用 `register()`，关闭调用 `unregister()`。只注册 Pulse 自己，不清理其它登录项。
- 需要批准时开关为关，说明「需要在系统设置的登录项里允许 Pulse。」，并可用「打开系统设置」跳到登录项。注册失败时开关为关，并显示失败原因。在系统设置里移除该项后，Pulse 下次读到的状态为关。

## 动效

Tab 选中胶囊、总览高度和工具栏里的页专属开关用同一段动画。总览交叉淡入，高度收到新页的卡片上，进程表只跟着下沿移动，不重建、不淡出。切到本机页时整页交叉淡入。行选中、侧栏、排序箭头、清空按钮和定位滚动都有短过渡。系统开启「减少动态效果」时直接跳转。采样数字和列表重排不加动画。

## 测试

- `swift test` 编译 `SamplingCore` 并跑 `Tests/SamplingCoreTests/`，覆盖纯投影、采样节奏、请求门闩、退出会话、退出路由，以及保存当前快照的文档、转义和文件替换。
- 部分 `*WiringSourceTests` 直接读 App 源码文本，校验视图接线。保存快照的接线测试只证明源码约束，不代替 SwiftUI、系统保存面板或 VoiceOver。
- CI（`.github/workflows/ci.yml`，`macos-15`）跑 `swift test`，再以 `CODE_SIGNING_ALLOWED=NO` 构建 App。
- 读取系统的代码和视图不在 `swift test` 里，需要按下面的清单在本机冒烟。
