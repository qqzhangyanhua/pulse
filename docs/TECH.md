# Pulse 技术设计（当前实现）

这份文档描述 `main` 上**现在**的实现。行为或口径改了，就在同一个 PR 里改这里对应的段落，不要在文末追加新的一期。

每一期落地前的设计稿归档在 [docs/specs/](specs/README.md)，只作历史参考，不作为决策依据。跨期的口径决定记在 [docs/adr/](adr/)。信息冲突时以代码为准，其次是 ADR、本文档和 PRD，最后才是归档稿。发现本文档和代码不一致，就在同一个 PR 里改本文档。

## 总体约束

- macOS 14+，SwiftUI 原生，单 Target、单进程。不拆 Helper / XPC，不装内核扩展。
- 非沙盒，`Pulse.entitlements` 不再是空 dict，只包含定位权限 `com.apple.security.personal-information.location`（用来显示 Wi-Fi 名称）。见 [ADR-0006](adr/0006-location-for-wifi-name.md)。Hardened Runtime 打开，公证直装（见 [RELEASE.md](RELEASE.md)）。
- 读不到就显示「—」「暂时读不到」「未采样」，**不写假 0**。真实 0 照常显示。
- 文案冷静：压力只有「正常 / 偏高」，不出现「危险 / 危急 / 泄漏」。菜单栏和界面都不用警报红。
- 可移植逻辑（Darwin / AppKit 无关）放进 `Package.swift` 的 `SamplingCore` 源列表，由 `swift test` 覆盖。

## 架构

```
PulseApp ─┬─ ContentView / MemoryDashboardView ── Views/*
          └─ PulseAppDelegate ── MenuBarController（NSStatusItem + NSPopover）
                 └─ MemoryDashboardVM（适配器，@MainActor，唯一 VM，活过窗口）
                    │ 只发布一份 DashboardCore。采样循环、perform、观察者注册留在适配器
                    │ SamplingRequestGate + SamplingClock + SamplingSession
                    ├─ DashboardCore（同步状态；变更返回 DashboardEffect）
                    ▼
             MemorySampler（actor，唯一采样器）
                 ├─ HostMemoryReader / SwapUsageReader / PressureProvider / KernelPressure
                 ├─ HostCPUReader（整机 + 每核）
                 ├─ HostNetworkReader / HostDiskReader
                 └─ ProcessEnumerator（proc_listpids / proc_pidinfo / proc_pid_rusage）
             HostMachineReader（只给本机页，不在采样器里）
```

- `MemorySampler.sample()` 每次产出一帧不可变的 `SampledFrame`：主机内存快照、进程行、选中进程详情、整机 CPU、最忙一核、主机网络 / 磁盘速率、Top5 内存序列、权限脚注。主线程只读这帧。
- 主窗、菜单栏、各资源页都读同一个 VM 的同一帧。没有第二个采样器，也没有第二条轮询。这个 VM 归 `PulseAppDelegate`，启动完成就 `start()`，关窗不释放。
- 仪表盘的同步状态在 `DashboardCore`（`MemoryDashboardVM` 只发布这一份 `core`）。采样应用、选中、页面、排序、过滤、结束进程、能耗页选中代次、定位 Top App 和 Top3 点击、网络连接与公网 IP、定位授权效果、GPU 与芯片温度的页面切换、降频提示与散热建议、电池卡片、本机信息、工具栏机型名，以及重试投影 `isRetrying` 和快照冻结的状态步骤都在这里，并返回 `DashboardEffect`。`isRetrying` 是采样门闩 `retrying` 的投影，不是第二套重试标志。公网 IP 查询和定位授权只在用户点击时返回。
- 适配器只保留同名只读转发、意图方法、`perform` / `performExternal`、采样循环，以及热状态、连接、Wi-Fi、电池和本机观察者的注册与注销。副作用从核心交到适配器，由适配器对宿主执行：采样器、`ProcessActions`、本机页和电池观察、公网 IP 传输、定位授权、`ProcessInfo` 热状态通知、读数和快照文件 IO。有窗口 App 的 pid 仍由适配器查询后传入。结束进程的结果、读数、门闩重试位、机型名和查询结果再作为输入交回 `DashboardCore`（例如 `noteMachineLabel`、`noteRetrying`、`finishQuit`、`finishPublicIPLookup`）。
- `DashboardCore` 放在 `Models/`，但是仪表盘状态，不是纯投影。同目录里其余类型仍是纯投影：输入现有字段，输出文案和状态，不采样、不存历史。
- 「保存当前快照」不新增采样器。它在主线程抄下已经发布的那一帧，做成预览和本机 HTML。

## 采样节奏与失败

- 前台（主窗可见且 App 激活）每 1.5 秒采一帧；主窗在后台或已关、只剩菜单栏时每 3 秒一帧（`SamplingPace`）。循环每 400ms 醒一次，只为及时察觉前后台切换，到期才采。
- 采样在 `applicationDidFinishLaunching` 开始，不等主窗出现。没有主窗时采样门保持窗口不可见，走后台 3 秒。带着主窗启动时，窗口锚点把采样门改回前台，第一段间隔仍是 1.5 秒。`start()` 幂等，窗口再次绑定不会开第二条循环。循环在适配器上（`start`、`tick`、`sleepInterruptible`，以及 `SamplingRequestGate`、`SamplingClock`、`SamplingSession`）。`DashboardCore` 不睡眠，也不读门闩。
- 关掉主窗不退出 App（`terminateAfterLastWindowClosed = false`），菜单栏继续用同一个采样器。`⌘Q` 才真正退出。
- 采样失败进入失败空态，保留上一帧的数据和曲线，不清零。七处失败空态共用 `SamplingRetryChrome`：按钮「重试」，等待中显示「正在重试…」。
- 手动重试和定时到期共享同一个在途请求（`SamplingRequestGate`）。在途时再点重试会并入当前请求，不会再排一帧。重试期间不会把「失败」退回「采样中」。失败相位由 `DashboardCore.retry()` 保持；适配器只执行 `requestRetryWake`（请求门闩并取消当前睡眠），再把门闩的 `retrying` 记成 `isRetrying`。

## 主机读数

| 读数 | 来源 | 缺失时 |
| --- | --- | --- |
| 已用 / 总量 / 分类条（App、联动、被压缩、已缓存） | `host_statistics64` + 页大小，按活动监视器的分类映射 | 整帧失败 |
| 压力档 | `kern.memorystatus_vm_pressure_level`：1 为正常，2 和 4 为偏高。读不到或未知值（含 0、3）不硬判，回退启发式（已用 ≥ 88% 或压缩 ≥ 18% 为偏高）。仍只有两档 | — |
| 交换已用 | `vm.swapusage`，返回长度必须一致 | 「— / 未采样」，不算整帧失败 |
| 换入 / 换出 | `host_statistics64` 的 `pageins` 和 `pageouts`，两帧页数差乘以页大小再除以间隔。包括交换和文件页，不是磁盘吞吐，也不读进程的 `ri_pageins` / `pti_pageins` | 第一帧、计数回退、读不到是「—」。真实 0 是「0 字节/秒」。缺这一对不算整帧失败 |
| 整机 CPU | `host_statistics(HOST_CPU_LOAD_INFO)`，两帧求差 | 第一帧「—」 |
| 最忙一核 | `host_processor_info`，两帧求差取最大 | 「—」 |
| 网络上行 / 下行 | `sysctl` `NET_RT_IFLIST2` 的 64 位 `if_data64` 计数，两帧求差。`getifaddrs` 的 `ifi_ibytes` / `ifi_obytes` 是 32 位，每 4 GiB 回绕，不再使用 | 「—」 |
| 磁盘读取 / 写入 | IOKit `IOBlockStorageDriver` Statistics，两帧求差 | 「—」 |
| 降频 | `ProcessInfo.thermalState` 的定性档位，只有 `serious` / `critical`。不读 SMC 温度，不读风扇转速。见 [ADR-0003](adr/0003-thermal-state-api.md) | 不显示 |
| 芯片温度 | HID 温度传感器里，产品名以 `PMU tdie` 开头的最高有限值，显示为整数 °C。只在本机页可见时跟着主采样拍读，不走 30 秒的 `HostMachineReader`。见 [ADR-0007](adr/0007-chip-temperature.md) | 「—」 |

`serious` / `critical` 时，内存、CPU、网络、磁盘、本机、GPU 各页总览在顶排指标上方放一张整行的散热建议卡片，菜单栏不读。名单先丢掉 Pulse 自己的 pid，以及 CPU 为 nil 的进程（nil 不当成 0，也不当成低于 10%），再按 CPU 百分比降序取前 3；百分比相同则 pid 较小的在前。前 3 名里有一个达到 10% 就列出这几名，刚好 10% 也列出。列出进程时，卡片第一行仍是「系统正在降频以控制温度」，然后才是这几行。测得到的前几名都严格低于 10% 时，不列行，只写「系统正在降频，但未检测到高负载进程」，不把两句叠在一起。丢掉 Pulse 和 nil 之后没有测到的百分比（全是 nil，或只剩 Pulse）时，不发布这张卡片，也不改 5 秒节流的时间戳，原来的一行降频句留在原处，下一帧测到 CPU 可以立刻换上卡片。卡片还在时，界面最多每 5 秒刷新一次，跟已有采样帧走，不另开 Timer。热状态一离开 `serious` / `critical`，卡片马上消失，不等这 5 秒。每行的「退出」调用 `ProcessActions.terminate`，没有额外确认，也不走 `confirmForceQuit`。进程页上，这个 pid 若正是当前选中，且 `ordinaryTerminate` 发出了结束会话，就用这次 `terminate` 的结果走和 `quitSelected` 相同的 `finish`；没发出会话也仍然 `terminate`。本机页和 GPU 页直接结束，不改选中。其它 pid 直接结束，不改选中。行图标在 `NSRunningApplication` 没有图标且可执行路径非空时，用 `NSWorkspace` 按路径取图标。降频提示还在、建议仍是 nil 时，原来的一行「系统正在降频以控制温度」留在原处。失败空态两者都不显示。

## 进程读数

- 进程列表来自 `proc_listpids`，每个 pid 读 `proc_pidinfo(PROC_PIDTASKINFO)` 和一次 `proc_pid_rusage`。任务信息成功后再读一次 `proc_pidinfo`（`PROC_PIDTBSDINFO`，136 字节）。短读则 `parentPid` 为 nil，不丢行，也不增加权限脚注。内核返回的 ppid 0 保留，不是失败。任务信息失败且 errno 为 EPERM 的进程不进表。这一帧这种失败的次数 N > 0 时，进程表底部写「另有 N 个系统进程没有读取权限」。ESRCH 不算，N 不跨帧累计，N 为 0 不写这句话。列表整个读失败时 `processListFailed = true`，表进失败空态，不写这句脚注，也不写 0。缺数仍是「—」。
- CPU%：`proc_pidinfo` 的用户态和内核态是 Mach 绝对时间 tick。每帧读一次 Mach 时间基，换成纳秒后再做两帧求差。时间基读失败或换算缺失时这一帧是「—」，不把原始 tick 送进速率，也不写成 0。第一帧、新出现的进程、计数变小仍是「—」。多核可以超过 100%。整机 CPU 和最忙一核仍用 `host_statistics` 的 tick，不经过这次换算。排序用换算后的百分比。
- 磁盘读取 / 写入：`proc_pid_rusage` 的累计字节两帧求差。读失败的进程显示「—」。
- 能耗影响 / 唤醒：同一次 `proc_pid_rusage`（`rusage_info_v6`）的 `ri_energy_nj`（纳焦）和 `ri_interrupt_wkups`，两帧求差。瓦特 = 纳焦差 / 秒 / 1e9，唤醒 = 次数差 / 秒。第一帧、计数变小、读取失败都是「—」。没有替代来源。v6 失败不另读 v4：内存仍回退驻留内存，能耗和唤醒缺失。见 [ADR-0002](adr/0002-process-energy-wakeups.md)。列名不表示活动监视器的能耗影响分数。CPU 页的两列就是这一对相邻帧，字段仍是 `energyWatts` 和 `wakeupsPerSecond`。能耗页的 1 分钟平均另算，不读这两个字段；1 小时排行用分钟桶。两者都见「能耗页」。
- 网络：没有按进程的数据来源。网络页的进程列写「暂不可用」，悬停说明「没有进程速率。主机下行和上行在总览。」。

### 内存口径

见 [ADR-0001](adr/0001-process-memory-footprint.md)。

- 进程「内存」= `ri_phys_footprint`（内存占用，和活动监视器的「内存」列一致）。真实 0 也算有效读数。
- 只有 `proc_pid_rusage` 读失败时才回退到 `pti_resident_size`（驻留内存），这一行带 `memorySource = .resident`（`ProcessMemoryChoice`）。
- 内存页详情（当前界面）：大数标题按大数那一行写「内存占用」，回退行写「驻留内存」。有总量时占比句是「占物理内存的 X%（按内存占用计算）」，回退行写「按驻留内存计算」；按 App 合并后只要有一个成员是回退，就写「部分按驻留内存计算」。没有总量时只写「占物理内存」，旁边加一句静态说明，不显示占比。占比句只描述大数那一行。大数下面另写归属：这一行 `groupedMemberCount` 有值时写「当前可见的 N 个同名进程合计」，N 含 1；计数值为空时写「当前进程（PID …）」，合并未命中也走这一句。主曲线标题用曲线所属进程自己的口径，「内存占用」或「驻留内存」，不借合并行，也不读「部分按驻留」。点数不少于 2 时摘要是「PID … · 最近 … · 峰值 …」；0 点或 1 点仍是「正在采集内存曲线」，摘要为空，不写 PID。CPU 辅曲线不写 PID。内存页且「按 App」生效时，大数先确认选中 pid 还在这一帧未合并的可见行里，再用该行当前名称匹配可见同名组合计。字节、占比、口径和 N 都来自这一合并行，N 含 1。选中 pid 不在可见行里时不借其它同名进程，退回该 pid 自己。CPU 页和其它页仍用 `displayedMemoryRow` 的 pid 查找。
- 其它页的详情标题仍是「内存」，不区分口径。

## 页面

`DashboardPage`：内存、CPU、能耗、磁盘、网络、本机、GPU 都可选。标签顺序以 `ResourceTab` 为准：内存、CPU、能耗、磁盘、网络、本机、GPU，不靠 `DashboardPage` 的声明顺序。冷启动在内存页。主窗用 frame autosave 记住尺寸和位置，不记页面、排序和过滤。能耗页已按 #140、#141、#142 和 #143 落地。GPU 页按 #160 落地，设备级键缺失时的 IOReport 回退按 #161：整页在本机之后，视图菜单没有 GPU，也没有 ⌘6。下面那一节是当前行为。本机冒烟还没有在 Mac 上跑过，清单保持未勾。

快捷键（「视图」菜单）：`⌘1`–`⌘5` 切到内存 / CPU / 磁盘 / 网络 / 本机，`⌘F` 聚焦名称过滤，`⌘⌫` 对选中进程做普通退出（过滤框有焦点时不注册，本机页和 GPU 页禁用）。`⌘C` 和「复制」是同一颗按钮，放在替换 `.pasteboard` 的命令组里，不在「视图」菜单里。名称过滤没有焦点时，这颗按钮带 `⌘C`，调用 `copySelectedProcessRow`：有 `selectedRow` 才写剪贴板，本机页和 GPU 在写入前返回。过滤框有焦点时，按钮不带快捷键，函数先把复制交给文字框，不写进程行。没有选中行，或当前是本机页或 GPU 页，不改剪贴板。强制退出和 GPU 没有快捷键。过滤框没有焦点时，内存页且「按 App」生效、并且选中 pid 还在这一帧未合并的可见行里，`⌘C` 和这颗「复制」按钮写出该可见同名组的现有制表符整行，第二列是成员数，N 为 1 时是 `1`。查找为空仍用 `selectedRow`。右键仍复制所点的那一行。滚动和文字焦点时的复制不改。`selectedRow` 仍先按 pid 查合并后的表，再查完整列表。列表出现以及 `processListScrollTarget` 变化时，这个值为空仍不调用 `scrollTo`。有值时，在同一次同步调用里把原 pid 映射到当前可见同名组的代表，再交给现有的那一次 `scrollTo`；N 为 1 时就是该 pid。查找为空仍用原来的目标。不新增触发。「占用最多的 App」的揭示不在这条路径里。

### 内存页

- 总览：紧凑双行布局。第一行用量大数与历史曲线、分类构成条（按类型与图例）；第二行仍是一行（内嵌趋势的压力档、可用、交换、换入、换出、占用最多的 App），没有换入换出曲线。换入 / 换出在可用 / 交换旁边，是整机 `pageins` / `pageouts` 的每秒字节数，包括交换和文件页，不是磁盘吞吐。第一帧、计数回退、读不到是「—」，真实 0 是「0 字节/秒」。不进菜单栏、快照或通知。降低纵向高度并扩充进程表可视区域。
- 进程表：名称、CPU、内存、线程，默认内存降序。表头可点排序，同值按 pid 升序。选中行可用 ⌘C 或右键「复制」，写成一行制表符分隔文本：名称、PID（按 App 合并时写成员数，含只有一个成员的组）、这一页表格里的读数。缺数是「—」；网络列仍是「暂不可用」。CPU 页带上能耗影响和唤醒，磁盘、网络页同一规则，列跟各页表格走。内存页且「按 App」生效时，底色和 `ProcessLine` 的文字颜色用同一次判断：选中 pid 还在这一帧未合并的可见行里，就涂包含它的当前同名合并行，N 为 1 时就是它自己。选中 pid 不可见、没有选中、合并关闭，或当前不是内存页时，仍是 `selectedPid == row.pid`。这只表示这一行包含原来的选中进程。列表的 `selection` 绑定仍是原来的 pid，不写成代表 pid，也不加读屏选中特征。滚动、`⌘C` 和右键复制不跟着这行高亮走。
- 工具栏胶囊开关，默认都关，只在本次会话内有效：
  - 「仅上涨」：只留下有「上涨」徽标的行。只在内存页。
  - 「仅窗口 App」：只留下 `activationPolicy == .regular` 的进程。只在内存页。列表用缓存在 `DashboardCore` 上的 pid 集：适配器在每次接受的采样之后查一次，并在「只看有窗口的 App」打开时再查一次，把得到的 pid 集交给过滤。开关关闭或不在内存页时不用这套 pid 过滤可见行。新开的窗口要到下一次接受的采样才出现在列表里。Top3 点击和进程树跳转是否关掉这个开关，用当时重新查到的 pid 集决定，这次查找不写进那份缓存。
  - 「按 App」：内存页、CPU 页和能耗页都有。内存页和 CPU 页把当前可见行按名称合成一行，内存、线程、CPU、磁盘相加，任何成员缺数则合计缺数。这两页的能耗和唤醒按有读数的成员相加，有成员缺失则保留部分和并在详情注明「部分读数」，全部缺失仍是「—」。选中落到该组内存最多的 pid。能耗页的求和用 1 分钟窗口，见「能耗页」。磁盘页和网络页不合并。这项在内存页、CPU 页或能耗页生效时，详情头不显示进程树按钮，已经打开的树会关掉；磁盘页和网络页不因此隐藏。
- 过滤顺序：名称过滤 → 仅上涨 → 仅窗口 App → 按 App 合并 → 表头排序。菜单栏 Top3、上涨 Top5 和「占用最多的 App」都读未过滤、未合并的完整列表。
- 过滤后无结果：「清空过滤」一次清掉名称、仅上涨和仅窗口 App，「按 App」保持不变（`clearMemoryPageFilters`）。只开「仅窗口 App」导致的空态也走「没有匹配的 App」，副句仍是「清空名称和仅上涨过滤。」，没有提到仅窗口 App。采样中、列表失败、无进程这几种空态优先。
- 「占用最多的 App」卡可点：确认 pid 还在列表且名称没变，必要时把名称过滤改成该名称，关掉「仅上涨」和「仅窗口 App」（「按 App」不变），然后用该卡片 pid 选中（`TopAppLocation`）。已经发出的这条命令，在内存页且「按 App」生效、并且卡片 pid 还在这一帧未合并可见行里时，滚动到当前可见同名组的代表；N 为 1 时就是该 pid。未命中才看 `sortedRows` 有没有原来的 pid：有就滚这个 pid，没有就不滚。卡片 pid、计划 pid 和选中 pid 仍是原来的数，不改成代表。本机冒烟清单的勾选不因这句改变。

### 上涨信号

- 窗口是选中进程或 Top5 进程自己的内存序列，最多 90 点（`ChartSampleRing`）。
- 不足 80 点：详情写「样本不足，暂不判断」，列表不显示。
- 满 80 点后，首尾净增超过 8 MiB **且**至少 60% 的相邻间隔上涨，才算上涨；中间可以有下降。不做斜率拟合，不判泄漏。
- 详情（当前界面）：「内存趋势 · 近期内存占用上涨」，旁注「当前进程近期趋势 · 基于现有内存占用」，上涨时同一组读屏文字里再加「这条趋势属于 PID …」。样本不足仍是「样本不足，暂不判断」，同一组读屏里再加单独一句「当前采样对象：PID …」。PID 取这次传进 `memoryTrend` 的 `curveRow`，也就是侧栏这份 `sidebar.detail.row`，不读可见组代表，也不在句里再读 `selectedPid`。没有上涨时不占位。旁注不改成 App 趋势，也不把 PID 写进旁注常量。下面有默认收起的「采样窗口与判断依据」。本机冒烟清单这一条仍未勾选。预期文字是：现有样本不足槽显示「当前采样对象：PID …」，PID 来自本次 `curveRow`（`detail.row`），沿原合并读屏。
- 列表：只有当前内存页排序下完整列表的前 5 个进程有序列（`MemoryGrowthTopSeries`），满足条件时显示「上涨」徽标。掉出前 5 的 pid 当轮丢弃序列。切到其它页时，Top5 仍按最后一次内存页排序算。「仅上涨」开关仍是 `MemoryGrowthListCopy.help` 这一整句，没有 PID。内存页按 App 的组行（`groupedMemberCount` 非空，含 1）在原本已有「上涨」徽标时，悬停和整行读屏共用的那份 `badge.help` 是原句直接接上「此上涨判断针对 PID …，不代表同名组合计趋势。」PID 是该徽标实际受评的 `row.pid`，不是 `selectedPid`。短标签仍是「上涨」。无徽标、非组行和其它页不追加。本机冒烟清单的勾选不因这句改变。

### CPU / 网络 / 磁盘页

- CPU 页：总览整机 CPU 与历史曲线、「最忙的一核」；表默认 CPU 降序。进程表另有「能耗影响」（瓦特）和「唤醒」（次/秒），可分别排序，缺数按低于 0 处理。这是相邻两帧，升序时缺数在真实 0 前面。能耗页不沿用这个比较。详情显示同样两项；按 App 合并时这两项用成员之和，有成员缺失时注明「部分读数」。工具栏有「按 App」，磁盘页和网络页没有。
- 网络页：总览主机下行 / 上行与曲线。下行 / 上行上方有「连接」卡片：类型是「Wi-Fi」「以太网」「其它」或「未连接」，状态是「已连接」「未连接」或「需要登录或配置」。`NWPathMonitor` 推送这两项，不进采样器，也不另开轮询；路径还没到时是「—」，不假装已连接。类型是 Wi-Fi 时另有信号行，格式如「强 (−55 dBm)」：RSSI ≥ −60 为「强」，−70 到 −61 为「中」，≤ −71 为「弱」。RSSI 为 0 或没有接口时是「—」，不是 0。以太网、其它、未连接和还没有路径时不显示这一行。信号随现有采样每帧读一次，不另开 Timer，也不挂在 `NWPathMonitor` 上，也不需要定位权限。类型是 Wi-Fi 时还有名称行。没点「允许」之前值是「—」，提示「需要定位权限才能显示 Wi-Fi 名称」。系统定位提示只由「允许」触发，不在启动、VM 初始化、采样或信号读取时出现。允许后显示名称，一行中间截断，悬停是完整名称；已经允许但读不到名称时仍是「—」，不再显示「允许」。拒绝或受限后是「—」和「定位未授权」，没有「允许」。同一张卡片上有公网 IP，以太网和还没有路径时也显示。按钮「查询公网 IP」才请求，先 `https://api.ipify.org`，失败或正文不是地址再试 `https://checkip.amazonaws.com`。去掉首尾空白后只接受 IPv4 或 IPv6，HTML 和其他正文都算失败并换下一个。成功显示地址、「查询于 HH:mm」和「复制」。失败把地址清掉，显示「—」和「查询失败」，可以重试。查询中再点没有作用。结果只留在内存里，不进采样、快照或菜单栏；下次启动回到按钮。进程网络列「暂不可用」；表默认 CPU 降序。
- 磁盘页：总览主机读取 / 写入与曲线；「读取」「写入」两列可分别排序，缺数的行按低于 0 处理（降序时排在最后）；默认按读写合计降序。
- 详情侧栏按当前页呈现主读数（`ResourceDetailPageProjection`）。
- 总览曲线在当前值缺失时附「历史曲线 · 当前值暂不可用」（`HistoryCurvePresentation`）。
- CPU / 网络 / 磁盘页名称过滤无结果时，「清空过滤」只清名称。

### 能耗页

当前行为（#140、#141、#142、#143、#144、#145）。口径沿用已合入的约定，不新增 ADR，不改 ADR-0002 的两帧公式。落地前的约定在 [specs/35-energy-page.md](specs/35-energy-page.md)。落地后以这一节为准，那份稿停改。

- 标签在 CPU 之后，标题「能耗」，符号 `bolt`。入口只有标签栏。视图菜单不增加能耗项，`⌘1`–`⌘5` 仍是内存 / CPU / 磁盘 / 网络 / 本机。
- 没有内存总览。表上方有「1 分钟 / 1 小时」两档，默认 1 分钟，不是第三个资源标签。1 分钟标题是「最近 1 分钟平均功率」。正文写：用这段时间里累计的能耗除以实际时长。不足 1 分钟时用已经采到的时长。读不到显示「—」，不显示 0。这不是活动监视器的能耗影响分数。1 小时标题是「最近 1 小时平均功率」。正文写：把这一小时里有读数的分钟耗电量相加，再除以这些分钟的实际时长。缺读数的分钟不补 0。这不是活动监视器的能耗影响分数。采样中的占位不另写「没有匹配的 App」。
- 同一处表上方另有一条只保存在内存里的曲线：最近 4 小时、240 个时钟分钟，到最新记下的那一分钟为止，重启后清空。每个点是这一分钟里进程两帧 `energyWatts` 非空合计的平均，单位是瓦特；没有非空样本的分钟留空，不补 0。有内置电池时叠加电量百分比，没有电池只画主曲线。电量只在选中能耗页时写入；离开该页的分钟电量留空，不写成 0。进程瓦特在其它页仍继续记。图例是「进程能耗合计」，不写成整机功耗。少于两个有瓦特的点时显示「历史曲线 · 当前值暂不可用」。
- 表只有三列：名称、「能耗影响」、「唤醒」。单元格沿用 `ProcessEnergyText`：「1.5 W」「0.0 W」「3.0 次/秒」「0.0 次/秒」或「—」。表头不写成「能耗影响(W)」或「唤醒/秒」；「W」和「每秒」在单元格单位里。产品锁里的这两个说法指口径。
- 默认能耗影响降序。名称第一次点为升序，能耗和唤醒第一次点为降序，再点翻转。同值按 pid 升序，不随方向翻转。离开再进入按现有换页规则回到这个默认排序。
- 能耗和唤醒的 nil 在升序、降序都排在所有非 nil 之后。真实 0 留在有值的一侧。名称排序不把 nil 沉底。CPU 页的「缺数低于 0」不变。
- 数字来自同一枚 `EnergyTick` 上的第二个和第三个消费者，不读 `energyWatts` / `wakeupsPerSecond`。采样帧另附按 pid 的 1 分钟窗口速率和 1 小时分钟桶速率；查不到就显示 nil，不回退到两帧字段。不把这两张表写进 `ProcessRow`。1 分钟仍是下面这条窗口。1 小时是分钟桶，见下一条。
- 平均 = 当前单调段里、年龄不超过 60 秒的最早一枚成功 tick 到最新一枚的计数差，再除以这两枚的墙钟。年龄按 `capturedAt`。超过 60 秒的 tick 丢掉，刚好 60 秒留下。瓦特 = 纳焦差 / 秒 / 1e9，唤醒每秒 = `ri_interrupt_wkups` 的次数差 / 秒。两项调用 `ProcessEnergyLoad.rates`。不把各帧瓦特再做平均，不插值，不把分母补成 60 秒。满窗时分母通常比 60 秒短不到一个采样间隔。Pulse 启动前没有采到的时间不补。
- 少于两枚 tick、任一计数变小、或时长 ≤ 0：两项一起为 nil，界面「—」。计数变小或时长 ≤ 0 时，段只留下新的这一枚，下一枚成功且不回退的 tick 才按短窗出数。差分为 0 是「0.0 W」或「0.0 次/秒」，不是「—」；一项为 0 时另一项可以是正数。
- 本帧纳焦或唤醒次数缺失：两项为 nil，已有 tick 保留，不记 0。下一枚成功 tick 若仍在 60 秒内且计数不减小，差值含这段累计，时长含这段墙钟。中间失败超过 60 秒、成功之后只剩一枚 tick：nil，不显示一条更长的平均。
- 1 分钟窗口只列出这一帧仍在进程列表里的 pid。离开列表就删掉窗口状态，再出现从无基线开始。1 分钟窗口不保留已退出进程。身份只有 pid。计数变小会切开复用后的新进程；计数没有变小则沿用今天两帧路径的限制，不新增进程世代或系统调用。
- 1 小时排行来自 `ProcessEnergyMinuteLedger`，不是把 1 分钟窗口拉长。身份是 `(pid, generation)`。当前在成功列表里的是这一代的活进程，保留最近接受的锚点，以及最多 60 个分钟桶，只在内存里。分钟按 epoch 整分向下取整。第一枚 tick、本帧读数缺失都不往桶里加。任一计数变小或时长 ≤ 0 时，若已有秒数 > 0 的桶，把这一代封成已退出，再开新的一代，新一代只有这一枚锚点，活进程的小时速率不含封存的纳焦；没有任何有秒数的桶则不产生已退出行。有效间隔的纳焦差、唤醒差和秒数全部加进结束 tick 所在的那一分钟。差分为 0 且秒数 > 0 是真实 0。没有有效间隔的分钟不建桶，也不补 0。`now` 距分钟起点超过 3600 秒的桶丢掉，刚好 3600 秒留下；每一代还多于 60 个就丢掉最老的，直到 60。瓦特 = 留下的桶的纳焦和 / 秒数和 / 1e9，唤醒 = 次数和 / 秒数和。不把每分钟的瓦特再平均，不把分母补成 3600。一个进程缺了几分钟不算「部分读数」。没有可用桶是「—」。离开列表把这一代封成已退出，桶留到超出 1 小时窗口；最后一个有读数的分钟超出后，这一代从排行移除。同一 pid 再出现，即使计数更高，也是新的一代，锚点是这一枚 tick，不并入已退出一代的桶。采样器记住已有的显示名；缺名或空白显示十进制 pid。已退出一代与活进程的小时速率分开；速率为缺失的一代不列出。1 分钟排行不显示已退出进程。进程列表没读到时不推进分钟桶，采样器里的桶、锚点和已退出一代留着；这一帧发布的小时速率和已退出列表都是空的，下一帧列表成功再发出。整帧采样失败不改已经发布的小时速率和已退出列表。仍是同一次 `proc_pid_rusage`，v6 失败不读 v4。
- 每次现有采样都更新窗口，包括停在别的页和关掉主窗之后。节奏仍是前台约 1.5 秒、后台约 3 秒。不增加 `proc_pid_rusage`，v6 失败不读 v4。
- 搜索沿用 `ProcessNameFilter`，只匹配名称。列表成功但没有进程：「还没有进程数据」。有进程但过滤后为空：「没有匹配的 App」，「清空过滤」只清名称。进程列表没读到，或整帧采样失败，优先于这两种，并使用现有重试文案，标题不写「CPU」。过滤框有字而列表本身为空时，不显示搜索空态。
- 工具栏有「按 App」，没有「仅上涨」和「仅窗口 App」。过滤顺序是名称过滤，然后按 App，然后表头排序。同名进程合成一行。代表 pid 与 `AppGroupProjection.combine` 相同：内存最大，平手取更小的 pid。`groupedMemberCount` 写在显示行上，含 1。能耗和唤醒按当前档位的速率分别走 `ProcessEnergyGroup.sum`：1 分钟用窗口速率，1 小时用分钟桶速率。不把这两张表写进采样行的 `energyWatts` / `wakeupsPerSecond`，也不用 CPU 页的两帧和。有读数的成员相加；有成员缺失则保留部分和，侧栏注明「部分读数」；全部缺失是「—」，不是 0。真实 0 参与相加。展示用的速率表按显示行的 pid 索引，只在这一页计算。未分组时就是该档位原来的速率。分组后的排序仍是这一页的 nil 双向沉底。「按 App」帮助是「同名进程合为一行。能耗和唤醒按有读数的成员相加，有成员缺失则标「部分读数」。」已退出一代不并进这个组，能耗也不加进组的和。
- 点行打开现有详情侧栏。侧栏的能耗影响和唤醒是这一行当前档位的速率：未分组是该 pid，分组是组的和，并带「部分读数」。不显示两帧 `energyWatts`。CPU 页投影仍读两帧字段。结束进程复用现有退出控件，`allowsProcessQuit` 为 true，`⌘⌫` 可用。按 App 开着时不显示进程树按钮，与 CPU 页相同。标题和正文跟着 1 分钟 / 1 小时切换。曲线在表上方，不放进内存总览。1 小时排行在活进程之外列出仍有速率的已退出一代，名称旁显示「已退出」。它们不并进「按 App」的组，仍走名称过滤和同一套 nil 沉底排序。已退出行不是结束目标：侧栏不显示「退出」和「强制退出…」，「正在退出…」、失败文案和已用内存说明仍留下。`quitSelected` 与 `forceQuitSelected` 不发信号，`⌘⌫` 不可用。`allowsProcessQuit` 仍为 true，活着的能耗行仍可结束。点已退出行不会把 `selectedPid` 设成复用了同一 pid 的活进程。能耗页记下选中时的活世代。这一代不再是该 pid 的活世代时，采样应用里清掉选中，因此不会退出新进程。其它页选来的空世代，只要这一行还活着，就绑到当前世代，不清选中。已退出且 pid 未被复用时保持选中。1 分钟排行不显示已退出进程。
- 有内置电池时，进程表上方显示电池卡片：电量百分比、电源（「电池」或「电源适配器」）、低电量模式（只在开启时标出）和时间。没有内置电池不显示卡片，台式机和只有 UPS 的机器因此隐藏，表仍在。百分比缺失是「—」，真实 0 是「0%」。读不到电源时电源是「—」，不猜成电池或适配器。
- 用电池时，时间是 `IOPSGetTimeRemainingEstimate` 的有限秒数（系统头文件的结果单位是秒）。不足 1 分钟写「剩余 N 秒」；其余按小时和分钟整除，余秒丢掉，例如「剩余 45 分钟」「剩余 1 小时」「剩余 1 小时 30 分钟」。未知（-1）或无限（-2）写「正在估算…」。
- 正在充电时，时间是 `kIOPSTimeToFullChargeKey` 的分钟数，写成「充满还需 X」。键缺失，或系统仍在计算（-1），写「正在估算…」。系统给出的 0 是「充满还需 0 分钟」。
- 接通电源且未充电：「已接通电源」，不显示时间。不根据百分比或功率推算时间。格式化系统给的秒或分钟不算推算。
- 只在能耗页选中时读取：进入时读一次，之后每 30 秒，离开即停。不进采样循环，不改 `HostMachineReader` 交给本机页的文案和字段。
- `⌘C` 和右键「复制」写成看得见的那一行：名称、第二列、能耗影响、唤醒。未分组第二列是 pid，数值是该 pid 当前档位的速率。分组后第二列是成员数（含 1），能耗和唤醒是组在当前档位的和。不写 CPU、内存、线程。小时值仍是瓦特，不是 Wh。
- 工具栏仍有「保存当前快照」。快照正文继续不写能耗和唤醒，也不写 1 分钟窗口。菜单栏不增加能耗区块。本机页电池的读取和文案不改。降频句不搬到这一页。

### 本机页

- 进入时读一次 `HostMachineReader`，停留期间每 30 秒刷新，离开即停。不在采样循环里。
- 身份区：机型（`hw.model`）、芯片、系统版本、核数与内存容量。
- 卡片：CPU（含「较上次」差值和曲线）、内存、磁盘已用（根卷）、电源（电量 / 电源类型 / 低电量模式）、已开机（含绝对开机时间）、交换、芯片温度（当前整数 °C，读不到是「—」；曲线最多 90 点，存未取整的摄氏度，读数缺失或与最后一点同一采样时间不追加，少于 2 点不画，刚进入和刚离开本机页都清空曲线）。芯片温度只在本机页可见时跟着主采样拍读，不走 30 秒的 `HostMachineReader` 刷新。有内置电池时，电源区另显示循环次数、健康度（满充容量 / 设计容量）和功率（放电为负）；没有内置电池不显示这一区，单项读不到只该项为「—」。电池来自 `AppleSmartBattery`，跟本机页同一次读取，不进采样循环。CPU、内存和交换直接用采样器的现有数据。
- 诊断三行：内存压力、磁盘空间（已用 ≥ 90% 为偏高）、CPU 负载（≥ 80% 为偏高）。能点的行跳到对应页。
- 没有进程表和过滤，退出命令禁用。

### GPU 页

- 整页，和本机页一样换页（减少动态效果时不播放页面动画）。没有进程表、名称过滤、仅上涨、仅窗口 App、按 App，也没有详情侧栏。进入时沿用已有的默认排序（内存降序），不新增 GPU 列，也不清 `selectedPid`。
- 顶上是与本机页相同的 `ThermalAdviceCard`，包括卡片上的退出。`allowsProcessQuit` 为 false，视图菜单的退出和 `⌘⌫` 禁用。复制选中行在写入前返回，不改剪贴板。
- 两个数：「GPU 使用率」和「GPU 占用内存」。百分比与 `CPUPercentText` 相同，一位小数，缺失「—」，真实 0 是 `0.0%`。字节与 `ByteFormat.memory` 相同，缺失「—」，真实 0 是「0 字节」。没有容量条，也没有内存曲线。
- 节点选择：带 `In use system memory` 的节点里，取字节最大的一台；字节相同保留输入顺序的第一台。两个数都来自这一台，不向另一台借，也不把多台加速器相加。键在但值不是字节数时，这一台仍占住选择，内存显示缺失。没有任何节点带这个键时，有资格的是：`Device Utilization %` 落在 0…100（含端点），或该键不存在且同一节点的 IOReport 设备百分比落在 0…100（含端点）。设备级键存在但小于 0、大于 100、非有限或读不出的节点没有资格，也不改读它的 IOReport。资格节点取输入顺序的第一台；都没有则两个数都缺失。选用节点上，设备级键存在且落在 0…100 就用它。该键存在但越界、非有限或读不出时，使用率缺失，不改读这一节点的 IOReport。该键不存在时，才用同一节点 0…100（含端点）的 IOReport 设备百分比，并按现有曲线规则记入；否则使用率缺失。这路设备通道是 IOReport 组 `GPU Stats`、子组 `GPU Performance States`：百分比是样本差里各状态驻留之和减去名为 `OFF` 的驻留，再除以驻留之和后乘 100。子组没有、还没有样本差、驻留之和为 0，或状态读不出时，百分比保持缺失，不记成 0。这路通道是整机的。读到百分比时，写到每一台缺 `Device Utilization %` 的节点上；键已经存在的不写。通道没有读数时这些字段保持缺失。没有任何节点缺这个键时不读这路通道。枚举到至少一台加速器、但都没有 `PerformanceStatistics` 字典时，补一个没有该键的空节点，让这路通道仍能成为使用率；已经有统计节点时不补空节点，空子项也不排到真实统计节点前面。打不开框架或符号失败也保持缺失。不订阅 Energy Model，不把 `Renderer Utilization %` 或 `Tiler Utilization %` 平均成使用率，不显示功耗、频率或温度。读取不调用 `IOServiceOpen`，用 `dlopen` 打开私有 IOReport，不把它加进链接阶段。内存只认 `In use system memory` 的字节，0 有效。忽略 `Alloc system memory`。
- 曲线最多 90 点，先例是 `SystemCPUHistory`。使用率缺失不记成 0，也不占一个点。少于 2 点不画。与最后记下的一点同一采样时间不追加。曲线只在进程内存里，应用重启后清空，不落盘。见 [ADR-0008](adr/0008-gpu-history-keeps-recording.md)。
- 页面切换在 `selectPage` 和 `focusMemoryPage` 里立刻生效，不等下一拍。刚进入不丢已经记下的曲线和读数。这一访还没有成功帧、且这一帧还在采样，才是骨架；失败且这一访尚未成功是现有的采样失败空态加重试；成功则写下使用率和占用内存，只在使用率有效时追加一点。刚离开不改已经记下的曲线和读数，也不发布这一帧。停留且失败：这一访已经成功则保留读数且不追加；从未成功则是失败空态，不是一直停在骨架。停留且成功：写下两个数并记上这一访已成功，即使两个键都缺。之后失败仍保留「—」或已有的数。这一拍没有读 GPU（节点为 nil）时不改这一页。
- 读取挂在现有主采样拍上（前台约 1.5 秒，后台约 3 秒），每一页都读，包括后台那一拍，不另开计时器。读到的使用率、占用内存和核心数不写菜单栏、快照、本机卡片或进程表。重试沿用现有的在途请求，不把 `.failed` 拨回 `.sampling`。
- 注册表键 `gpu-core-count` 在加速器条目上，与 `PerformanceStatistics` 同级。有正整数时，GPU 页读数区显示「N 核 GPU」；缺失、0、负数、小数或布尔值则不显示这一行，也不写成 0。多台加速器取输入顺序里第一个正整数，不相加。成功帧换成这一帧的数，这一帧没有则隐藏。失败、采样中和离开不改已经显示的核心数。不调用 `IOServiceOpen`。本机页不显示。

### 详情侧栏与退出

- 选中一行打开侧栏：图标、名称、内存 / CPU 大数、内存主曲线、CPU 辅曲线。切进程时两条曲线清空重采。常见系统进程附一句本地说明（`ProcessGlossary`）。说明下面是可安全退出判断和一句理由。判断只有「可以退出」「退出后会自动重启」「不建议退出（系统进程）」三档，按进程名去掉首尾空白后精确匹配，区分大小写。说明库里没有的名字不显示说明，也不显示判断，不留空行。进程表、散热建议卡和 GPU 页不显示这句判断。
- 各资源页的详情都有「进程信息」，在标题下面、当前页读数上面。启动时间对所有进程可见，来自同一次 `PROC_PIDTBSDINFO` 的秒，格式 `yyyy年M月d日 HH:mm`；读不到是「—」，真实 0 仍是 1970 的时间。签名只写「Apple」「开发者：团队名或 team ID」「未签名」；读不到是「—」。只有进程通过转译运行时才多一行「通过 Rosetta 运行」，读不到这一标记就不显示这一行。签名和 Rosetta 只在选中的 pid 变化时读取，结果留在这一节里，不进 VM、菜单栏、快照或通知。同一次 BSD 信息读取还把 uid 写进进程行；`isOwnUser(rowUid:selfUid:)` 用它判断是不是本用户进程，缺 uid 不算。按 App 合并时，uid 和启动时间跟代表进程走。
- 详情头在关闭按钮旁有进程树：`arrow.triangle.branch`，提示「进程树」。点开后侧栏换成这棵树，用未过滤、未合并的 `vm.rows`。`parentPid` 为 nil 或 0 时没有父节点，不是占位。本帧没有的非 0 父进程是灰色占位「(PID xxx - 无权限)」，名字不可点，也不写内存；有子节点时仍可展开。非占位节点显示名称、PID，内存是现有的 `memoryBytes`（内存占用口径），不是新的读数。当前进程用选中底色标出。打开时展开全部祖先、当前进程和它的直接子进程，更深的折叠；之后可手动改，采样刷新不重置。返回会选中打开树时的那个进程。点非占位节点和返回都调用 `selectPidIfPresent` 并关掉树。点节点或返回时，若「仅上涨」或「仅窗口 App」会清掉这个 pid，就关掉对应开关，名称过滤不动。内存页、CPU 页和能耗页在「按 App」生效时不显示按钮，已经打开的树会关掉；磁盘页和网络页不因为这个开关隐藏。
- 有应用对象的进程，包括登录窗口、程序坞、访达：「退出」走 `NSRunningApplication.terminate()`，等待最多 2.5 秒。失败后显示「强制退出」，先弹系统 `NSAlert` 确认，再 `forceTerminate()`。这条路径不发信号。
- 没有应用对象时，在 `ProcessActions` 里用 `proc_pidpath` 读可执行路径。路径缺失，或路径等于 `/System`、`/usr/libexec`、`/usr/sbin`、`/sbin`，或以这些前缀加 `/` 开头：不发信号。进程还在则请求失败，已经不在则未找到。其余普通退出发 SIGTERM，不另加确认；强制退出仍先弹原来的确认框，确认后发 SIGKILL，取消不发信号。
- 信号发出后仍用原来的等待、超时和退出记录（普通 2.5 秒，强制 2 秒）。`kill` 返回 ESRCH 视为未找到，其它失败视为请求失败。侧栏失败文案仍是「未能退出。可以请系统立即结束该进程。」和「系统未能结束该进程。」不按 uid 再拒绝，按钮可点规则不变。
- 退出结果按 pid 记在会话内（`ProcessQuitOutcome`）。进程消失后侧栏冻结在最后一帧，失败卡留在原处可重试。冻结卡的占比分母用消失前最后一次有效总量（`LastLiveTotalReducer`）。
- 退出成功、进程从列表消失后，在第 3 个成功采样点比较整机已用内存：减少达到 50 MiB 写「已用内存约减少 X」，否则写「已用内存变化不明显」。基准缺失、中途失败或切走时不显示。

## 保存当前快照

工具栏有单独的「保存当前快照」，各页都在，包括本机页。它不在过滤胶囊那一组里，也不跟随「仅上涨」「仅窗口 App」「按 App」。

点击时在主线程同步冻结最近一帧已经发布的有效采样：`snapshot != nil` 的那份主机快照，以及同一次发布里的 `rows`、整机 CPU、最忙一核、网络和磁盘。不调用采样器，不读本机页事实，不读降频提示，不读曲线。`samplingFailed == true` 时仍冻结上一份，采样时间保持 `snapshot.capturedAt`。没有有效帧时只提示「暂无可保存的采样，请稍后重试」，不打开预览，不写文件。

`savedAt` 是点击冻结的时刻，界面写「快照生成时间」。预览停留、系统保存面板、同帧重试和写盘都不另取时钟。预览和文件用同一份 `SnapshotDocument`：采样时间、快照生成时间、一句「非实时」、主机内存（已用、总量、App / 联动 / 被压缩 / 已缓存、交换）、压力两档、整机 CPU、最忙一核、网络下行 / 上行、磁盘读取 / 写入，以及未过滤完整进程列表按内存占用降序、同内存再按 pid 升序的前 5 行。不是当前表头排序，不是过滤后的表，也不是按 App 合并后的行。不足 5 个时写「当前只有 N 个进程。」列表没读到时写「进程列表没有读到。」，不把空表说成 0 个进程。名次只表示内存占用顺序。

每一行只有 pid、显示名、内存、内存来源（内存占用或驻留内存）、CPU%、线程数。不写路径、包标识、命令行、曲线、进程磁盘、能耗或唤醒，也不写能耗页的 1 分钟窗口。主窗其它位置的缺数仍是「—」。这份文档里缺失写「不可用」，真实 0 仍是「0 字节」「0.0%」或「0 字节/秒」。非有限浮点在做成文档前视为缺失。可见时间用调用方传入的日历和时区，格式 `yyyy-MM-dd HH:mm:ss`。

「隐藏进程名」默认关。打开后预览和将要写入的文件立刻把名称换成「已隐藏」，冻结值里的原名不改。文件是自包含的 UTF-8 HTML，扩展名 `.html`，`<title>` 固定为「Pulse 采样」。采样文本先转义再进正文；不写脚本、事件属性或链接。默认文件名是 `Pulse-快照-yyyyMMdd-HHmmss.html`，用的是 `savedAt`，不含进程名。

「保存到本机」才打开系统保存面板，不关闭系统自带的替换确认。这一次面板绑在打开它的那份预览上；同一份预览上一次面板还没结束时不再开第二个。回调如果碰到已经关闭或换成另一份预览，不写文件，也不改那份新预览的状态。同一次预览里取消面板不写文件。确认时写入的是当时的隐名版本，只有写入成功才显示「已保存」。取消预览，或取消保存面板，都不写文件；取消面板后预览还在。写入先落在目标同一目录的临时文件，再替换到目标。失败时目标原有字节保持不变，预览留着同一份冻结，提示「没能写入所选位置。这一份采样还在，可以再试。」只有替换成功才显示「已保存」。保存成功后如果「隐藏进程名」的实际开关变了，「已保存」撤掉，改为「隐藏进程名已改变。当前预览还没写入文件，请重新保存。」取消保存面板或再次写入失败都不会把这份新预览说成已保存；开关设成当前值则不撤。冻结的采样、采样时间、快照生成时间和默认文件名都不变，原来的文件要等下一次写入成功才替换。应用不打开这个文件。回看是用户稍后用系统打开那份本地 HTML。没有应用内导入、历史列表或历史 PID 操作。

## 菜单栏

- 状态项画一个压力色点：正常为冷静绿，偏高为琥珀，无数据或失败为灰，并附提示「暂时读不到」。默认栏上没有文字。设置里可选「仅色点」「色点 + 已用内存」「色点 + CPU」，默认仅色点；后两种在色点旁显示对应读数，缺失为「—」，数字等宽。选择存在 UserDefaults，重启后保留。`⌘,` 或轻量条里的「设置」打开设置窗口。
- 压力升到偏高时发一条系统通知，默认开，设置里可关。同一轮偏高只发一次；连续正常满 5 分钟后才重新可发。缺帧或采样失败不发，也不重置这一轮。文案是「内存压力偏高，可以看看谁占得最多」，有占用最多的 App 时带上名字。点击走「打开 Pulse」的同一条路径，打开主窗内存页。系统拒绝通知权限时不弹错误，设置里显示「系统通知未授权」。
- 左键弹出轻量条，右键或 Control 点击弹出「退出 Pulse」。
- 轻量条自上而下：压力一行、「已用 xx GB」一行、最忙一核达到 90% 时的「最忙的一核 · xx%」（可选），然后是 Top3 进程（名称 + 内存），最后是「打开 Pulse」和「设置」。
- Top3 用最后一次内存页表头排序，取完整列表的前 3 个，不受过滤影响。少于 3 个时不补位。
- 点 Top3 某行：关掉轻量条。PID 还在完整 `rows` 里时，先只调整挡住它的名称查询、「仅上涨」或「仅窗口 App」，再选中，然后只调用一次 `MemoryDashboardVM.focusMemoryPage`，最后只激活主窗。不调用 `onOpenPulse`，也不调用 `PulseAppDelegate.focusMemoryPage`。PID 已经不在列表里时不调整过滤、不写这个 PID、不选同名替代，仍是一次 VM 切页和一次激活。「打开 Pulse」、通知点击和重开主窗仍只走 `PulseAppDelegate.focusMemoryPage`。Mac 上的主窗激活、滚入视口、焦点、VoiceOver，以及下一次采样之后的终态，都还没验。

### Top3 点击后继续诊断

只改菜单栏 Top3 进程行这一次点击。目标是：被点的 PID 还在完整 `rows` 里时，切到内存页后仍然选中它、看得到它，并进入现有详情和退出操作。不新开页面、弹窗或搜索框焦点，不自动把焦点放进退出按钮。鼠标和键盘都走轻量条里现成的 `Button`，再进 `MenuBarPopoverTap`。

当前生产顺序，对照 `2fe7bcd` 的源码，不是 Mac 上点出来的：`MenuBarController.handlePopoverTap` 按 `MenuBarPopoverTap.steps` 执行。进程行是 `dismissPopover`，然后 `selectPidIfPresent`（`ProcessSelection.acceptedPid` 对照完整 `rows`），然后 `onOpenPulse`，也就是 `PulseAppDelegate.focusMemoryPage` → `MemoryDashboardVM.focusMemoryPage`。共享的 `focusMemoryPage` 自己不写入被点 PID。它先走 `DashboardNavigation.focusMemoryPage`：从别的页进来时排序恢复内存页默认（内存降序）；已经在内存页则保持当前排序。接着 `applyRisingOnlySelection`，再 `applyWindowedOnlySelection`。`MemoryGrowthRisingFilter.selectedPid` 在内存页且「仅上涨」开着、该 PID 没有列表徽标时返回 `nil`，名称查询不参与这道清选中。`WindowedAppFilter.selectedPid` 在「仅窗口 App」开着且 PID 不在窗口集时返回 `nil`。所以 pid 4 还在 `rows` 里、仅上涨开着、又没有徽标时，选中会在切页后变成空。这不是把共享清选中函数放宽就能交差的缺口。

已锁定的状态顺序是收起，然后在一次 `MemoryDashboardVM.focusMemoryPage` 之前做准备和选中。窗口激活跟在这一次切页后面，不再借 `onOpenPulse`。只允许在进程行、且 PID 仍在 `rows` 里时做这次准备。准备只动挡住这个 PID 的过滤：

- 名称查询：去掉首尾空白后为空，或 `ProcessNameFilter.apply` 仍留下该 PID，查询原文保持。否则把查询设成空字符串。不改成该进程的全名。
- 「仅上涨」：开关开着且 `MemoryGrowthList.badge` 对该 PID 为 `nil` 时才关掉。已有徽标则保持开。
- 「仅窗口 App」：开关开着且该 PID 不在现有窗口集里时才关掉。窗口集仍是 `WindowedAppLookup` 交给 `WindowedAppFilter` 的那一次，不另定义哪些进程有窗口。已在集里则保持开。
- 「按 App」不改。准备不写排序。

准备之后仍是现成的 `selectPidIfPresent`，然后只调用一次未改动的 `MemoryDashboardVM.focusMemoryPage`。这一次就是全部状态切页：适配器调用 `DashboardCore.focusMemoryPage`，核心做 `DashboardNavigation.focusMemoryPage`、`publishMemoryPageSort` 和两道清选中，并返回本机观察效果；适配器再执行 `syncMachineWatch`。清选中看到的是调整后的开关，所以被点 PID 留下来。详情仍绑定这个 `selectedPid`。`groupedByApp` 保持时，现有 `processListScrollTarget` 再经 `MemoryRevealGroupRow` 滚到可见组代表；代表可以不是被点 PID。选中、侧栏和退出仍是被点 PID，不换成代表。这里的 `focusMemoryPage` 是 VM 上的那个，不是 `PulseAppDelegate.focusMemoryPage`。

点击时 PID 已经不在 `rows`：不做这次准备，不写这个消失的 PID，也不选同名的另一行。然后仍是一次 `MemoryDashboardVM.focusMemoryPage`。不保证原来的选中还在，因为这一次共享清选中仍可能按现有开关清掉它。控制器接着只做一次窗口激活，不再切页。

现码没有「只激活、不切页」的函数。`MenuBarController.install` 收来的 `onOpenPulse`，在 `PulseAppDelegate.didLaunch` 里就是 `self.focusMemoryPage`。`PulseAppDelegate.focusMemoryPage` 先 `dashboard.focusMemoryPage()`，再 `NSApp.activate`，已有主窗则 `deminiaturize` / `makeKeyAndOrderFront`，否则 `openMainWindow`，然后改 `sceneActive` 并 `applyPace`。Top3 若在状态切页之后再调用 `onOpenPulse`，状态切页会跑第二次。所以 Top3 不调用 `onOpenPulse`，也不调用 `PulseAppDelegate.focusMemoryPage`。窗口激活用一条现在还不存在的 Top3 回调，只做上面这一段激活，不调用 `dashboard.focusMemoryPage()`。`PulseAppDelegate.focusMemoryPage` 的函数体不改，普通打开和通知仍只走它。

| 职责 | Top3 进程行 | 「打开 Pulse」 | 通知点击、重开主窗 |
| --- | --- | --- | --- |
| 收起轻量条 | `handlePopoverTap` 一次，在状态之前 | 同左 | 不走这里 |
| 过滤准备 | 仅 PID 仍在 `rows` 时，规则见上 | 不做 | 不做 |
| 选中 | `selectPidIfPresent` 一次 | 不写 | 不写 |
| 状态切页 | `MemoryDashboardVM.focusMemoryPage` 一次 | 含在下面这一次共享入口里 | 同左 |
| 窗口激活 | 新的只激活回调一次 | `onOpenPulse` 一次，即未改动的 `PulseAppDelegate.focusMemoryPage` | 通知闭包和重开直接调用这个 `focusMemoryPage` |

Top3 进程行只按这个顺序：`dismissPopover`，生产入口（需要时准备，然后选中，然后 `MemoryDashboardVM.focusMemoryPage` 一次），然后只激活回调一次。「打开 Pulse」仍是收起之后 `onOpenPulse` 一次，不进生产入口，也不再加只激活回调。两道 `selectedPid` 门的函数体不改。

跨页进入内存页仍只由现有 `DashboardNavigation.focusMemoryPage` 恢复内存默认排序。已经在内存页则保持进入点击前的排序。本项不再写一次排序。

后续采样仍可能改 `rows` 和上涨序列，终态可以和点击当时不同。这一节不把该竞态说成已解决。Mac 上的主窗激活、行是否真的滚进视口、焦点和 VoiceOver 都还没跑。纯模型和源码测试不能代替这四项。

把 `ProcessSelection.applying` 和未改动的 `MemoryGrowthRisingFilter.selectedPid` 手工串起来，只能证明共享上涨门在「仅上涨」开着且没有徽标时，会把已经写下的 pid 4 清成 `nil`。这只是共享门的缺口证据，不是 Top3 验收。验收不能靠测试在调用前自己插入准备，也不能靠放宽 `focusMemoryPage` 或这两道 `selectedPid`。

Top3 验收调用 `handlePopoverTap` 使用的那一个生产入口，断言的是控制器按上表调度完之后的状态，不是入口内部在 `MemoryDashboardVM.focusMemoryPage` 之前的中间选择。送进去的是真实状态：当前 `selectedPid`、`DashboardNavigation`、名称查询、「仅上涨」、「仅窗口 App」、「按 App」、`rows`、上涨序列和窗口集。同一次结果还带上这次调度：状态切页 1 次、窗口激活 1 次、`onOpenPulse` 0 次。红和绿是同一次用户动作（点进程 4）和同一句最终断言：这一次清选中跑完之后的 `selectedPid` 等于 4。按今天的语义，这一次门会把它变成 `nil`。变绿只在入口内部、于那一次 `MemoryDashboardVM.focusMemoryPage` 之前加上已锁定的准备。测试不写准备，也不再调用 `onOpenPulse`。

新增这个入口时，函数体先保持今天的进程行语义：还在才 `selectPidIfPresent`，然后 `MemoryDashboardVM.focusMemoryPage` 一次，不做准备。控制器随后只走新的激活回调一次。测试因此能编译。失败是最终选择为 `nil`，不是找不到符号。这道红记下之后，只把准备放进入口内部。同一句断言变成 4。源码接线读 `handlePopoverTap`：进程行是收起、该入口、只激活回调，这个顺序里 `onOpenPulse` 出现 0 次，`MemoryDashboardVM.focusMemoryPage` 只出现在入口里的那一次；「打开 Pulse」分支仍是收起后 `onOpenPulse` 1 次，且不调用该入口。`PulseAppDelegate.focusMemoryPage` 仍先 `dashboard.focusMemoryPage()` 再激活。通知闭包和重开仍只调用它。直接调用 `MemoryGrowthRisingFilter.selectedPid`，在仅上涨开着且无徽标时仍返回 `nil`。

下面这些都走同一套控制器调度。Linux 上的 `swift test` 会调用这个入口；那不是 Mac 主窗激活，也不是下一次采样之后的终态：

- 名称、仅上涨、仅窗口各自只在挡住该 PID 时调整；一起挡住时一起调。查询可匹配或空白、已有上涨徽标、已在窗口集的保持。最终选择是被点 PID。状态切页 1 次，激活 1 次，`onOpenPulse` 0 次。
- 目标已不在 `rows`：不准备，过滤保持原样，不写入该 PID，不选同名替代，然后仍是一次 `MemoryDashboardVM.focusMemoryPage`，再激活 1 次。`onOpenPulse` 0 次。
- 「打开 Pulse」不准备，`onOpenPulse` 1 次。通知点击不进这个入口，仍只调用 `PulseAppDelegate.focusMemoryPage`。
- 「按 App」开着，且组代表和被点 PID 不同：调度留下的选择和操作 PID 是被点的那个。揭示 id 再用现成 `MemoryRevealGroupRow` 从这次最终状态计算，可以是代表。
- 已在内存页时排序不变；从其它页进来时仍是现有内存默认排序。不另写一次排序，也不把状态切页再跑一遍。

这些调用不是 Mac 主窗激活、行是否滚进视口、焦点或 VoiceOver，也不是下一次采样之后的终态。

## 设置

- 「登录时打开 Pulse」的开关每次从 `SMAppService.mainApp.status` 读取，不另存布尔值。只有已启用为开；未注册为关。Pulse 启动时不会自己注册。打开调用 `register()`，关闭调用 `unregister()`。只注册 Pulse 自己，不清理其它登录项。
- 需要批准时开关为关，说明「需要在系统设置的登录项里允许 Pulse。」，并可用「打开系统设置」跳到登录项。注册失败时开关为关，并显示失败原因。在系统设置里移除该项后，Pulse 下次读到的状态为关。

## 动效

Tab 选中胶囊、总览高度和工具栏里的页专属开关用同一段动画。总览交叉淡入，高度收到新页的卡片上，进程表只跟着下沿移动，不重建、不淡出。切到本机页时整页交叉淡入。行选中、侧栏、排序箭头、清空按钮和定位滚动都有短过渡。系统开启「减少动态效果」时直接跳转。采样数字和列表重排不加动画。
