# Pulse 产品需求（当前范围）

> 好看的 Mac 资源诊断器：外表像活动监视器，任务按诊断走。内存是主线，CPU、能耗、磁盘、网络、本机和 GPU 页提供同一套冷静读数。能耗页按最近 1 分钟或 1 小时平均功率排行，并显示最近 4 小时的进程能耗合计。

仓库 [qqzhangyanhua/pulse](https://github.com/qqzhangyanhua/pulse)。暂名 Pulse，正式品牌待定。栈：SwiftUI 原生，公证直装，不做 Electron。

这份文档写**当前**范围和验收。新需求落地后，在同一个 PR 里更新这里。一期的原始需求见 [specs/00-prd.md](specs/00-prd.md)。实现细节见 [TECH.md](TECH.md)。

## 问题与用户

macOS 自带的活动监视器信息密度高，很难一眼看出「谁在吃内存、压力是否偏高」。用户需要一个好看又好用的本地工具，在卡顿或内存吃紧时快速找到并处理进程。

| 项 | 内容 |
| --- | --- |
| 主用户 | 日常 Mac 用户和开发者（同一界面） |
| 情境 | 机器变慢、内存压力升高、怀疑某个 App 占用异常 |
| 要完成 | 看清总览，找到嫌疑进程，安全退出或强制退出 |
| 平台 | 仅 macOS 14+ 桌面端 |

## 定位与成功标准

- 默认进入内存页，进程表按内存占用降序。
- 压力状态优先展示（正常 / 偏高），文案冷静，没有吓人的告警。
- **成功标准**：用户能在约 30 秒内定位吃内存的进程并安全退出。

## 当前范围

| 模块 | 要求 |
| --- | --- |
| 内存页 | 用量大数、分类条、压力档与曲线、可用 / 交换 / 换入 / 换出 / 占用最多的 App。换入 / 换出是整机页计数的每秒字节数，没有曲线；缺数是「—」，真实 0 仍是 0。进程表（名称、CPU、内存、线程），默认内存降序；名称过滤、仅上涨、仅窗口 App、按 App 合并 |
| 进程内存 | 按内存占用（footprint）显示，读不到时回退驻留内存并标明 |
| 上涨信号 | 选中进程的「内存趋势」软信号；列表前 5 名的「上涨」徽标；不判泄漏 |
| 详情侧栏 | 图标与名称；当前页的主读数；内存主曲线、CPU 辅曲线；常见系统进程的一句说明；退出（主）/ 强制退出（次，系统确认）；退出后的已用内存变化；进程树（父进程链和子进程，节点带内存；点节点跳到该进程；返回回到原详情） |
| CPU / 网络 / 磁盘页 | 主机读数与历史曲线；网络页另有连接状态（已连接 / 未连接 / 需要登录或配置）、类型（Wi-Fi / 以太网 / 其它 / 未连接）和 Wi-Fi 信号强度（强 / 中 / 弱，带 dBm）；Wi-Fi 名称只在点击「允许」并获得定位权限后显示，拒绝时显示「定位未授权」，信号不依赖该权限；公网 IP 是这款应用的第一次出站请求，只在点击后手动查询，启动和后台都不发；CPU 页含最忙一核，以及进程能耗影响（瓦特）和唤醒；磁盘页读取 / 写入分列排序；进程网络速率暂不提供 |
| 能耗页 | 标签在 CPU 之后。运行中进程默认按最近 1 分钟平均功率降序，可切到最近 1 小时。1 小时把有读数的分钟耗电量相加，再除以这些分钟的实际时长，缺的分钟不补 0。1 小时排行保留已退出进程，名称旁标「已退出」，不能结束。列是名称、能耗影响（瓦特）和唤醒（次/秒），可排序、可按名称搜索，可按 App 合并。点行打开详情并可结束进程。缺读数是「—」并排在最后，真实 0 仍是 0。沿用 ADR-0002，不声称等于活动监视器的能耗影响分数。不改 CPU 页这两列，不改本机页电池。有内置电池时，表上方显示电量、电源、低电量模式和时间（剩余、充满还需，或已接通电源）；没有电池则隐藏卡片。表上方另有最近 4 小时、240 分钟的进程能耗合计曲线，缺读数留空；有内置电池时叠加电量。见 #140、#141、#142、#143、#144、#145 |
| 本机页 | 机型、芯片、系统、容量、开机时间、芯片温度、电源、磁盘剩余、交换与当前负载；有内置电池时显示循环次数、健康度和功率；诊断项可跳到对应页 |
| GPU 页 | 标签在本机之后。整页是「GPU 使用率」「GPU 占用内存」、一条最多 90 点的使用率曲线，以及与本机页相同的散热建议卡片（含其退出按钮）。读数来自加速器已发布性能统计里的 `Device Utilization %` 和 `In use system memory`（字节）。带「In use system memory」的节点里取字节最大的一台，并列保留输入顺序的第一台，两个数字都来自这一台，不向另一台借，也不把多台相加。没有任何节点带这个键时，有资格的是：`Device Utilization %` 落在 0…100（含端点），或该键不存在且同一节点的 IOReport 设备百分比落在 0…100（含端点）。设备级键超出 0…100、非有限或读不出的节点没有资格。资格节点取输入顺序的第一台。选用节点上，存在的设备级键照用；超出 0…100、非有限或读不出时，使用率缺失，不改读 IOReport。该键不存在时，才用同一节点有限且落在 0…100（含端点）的 IOReport 设备百分比。通道是 IOReport 组 `GPU Stats`、子组 `GPU Performance States`（`OFF` 以外的驻留）。认不出的通道保持缺失。内存只认这个字节键，0 有效，不是字节数则缺失。百分比一位小数，缺失「—」，真实 0 是 `0.0%`；字节按内存格式，缺失「—」，真实 0 是「0 字节」。没有容量条，没有进程表、名称过滤、仅上涨、仅窗口 App、按 App 或详情侧栏。视图菜单不增加 GPU，也没有 ⌘6。离开即清空曲线且不发布这一帧；再次进入先丢掉上一访的读数和曲线。这两个数不写进菜单栏、快照、本机卡片或进程表 |
| 菜单栏 | 压力色点，默认栏上无文字；设置可选色点 + 已用内存或色点 + CPU（缺失为「—」，重启后保留）。轻量条：压力、已用内存、最忙一核（≥ 90% 时）、Top3 进程、打开 Pulse、设置。压力偏高时发一条系统通知（默认开，可关），同一轮一次，连续正常满 5 分钟后可再发；点击打开内存页。权限被拒时设置说明「系统通知未授权」 |
| 体验 | 前台采样约 1.5 秒；降频提示；键盘快捷键；选中进程行可复制；记住主窗尺寸；尊重减少动态效果；设置里可打开「登录时打开 Pulse」（默认关，只注册自己） |
| 保存当前快照 | 手动冻结最近一帧已发布采样，先只读预览，再存成一份本机静态 HTML。显示采样时间、快照生成时间、非实时、主机内存 / 压力 / CPU / 网络 / 磁盘，以及未过滤进程按内存降序的前 5 行。可隐藏进程名。缺失写「不可用」，真实 0 仍是 0。回看是直接打开那个文件 |
| 分发 | 公证直装；Hardened Runtime；不做 App Store 沙盒 |

## 关键状态（必须有）

无选中空态；采样中；采样失败（可重试）；进程列表读取失败；压力正常 / 偏高；过滤无结果（可一次清空）；退出中 / 失败；读数缺失显示「—」而不是 0。能耗页上，搜索无结果和没有运行中的进程是两种空态；真实 0 仍显示为 0。保存的快照里，缺失写「不可用」，真实 0 仍显示为 0。GPU 页刚进入、这一访还没有成功帧时是采样骨架；失败且尚未成功是可重试的采样失败空态。成功后两个数都写上，即使都缺；这一访已经成功后再失败，保留这两个数，曲线不追加。使用率缺失不记成 0，少于 2 点不画曲线。

## 验收标准

逐项清单见 [TECH.md「本机冒烟清单」](TECH.md#本机冒烟清单)。产品层面的底线：

- [ ] 冷启动在内存页，进程表按内存降序
- [ ] 过滤和开关组合后列表正确，无结果有空态
- [ ] 选中进程后侧栏曲线正确，切换进程后重采
- [ ] 退出走 `terminate`；失败后可强制退出，且有系统确认
- [ ] 前台采样约 1–2 秒，自身无明显卡顿、占用克制
- [ ] 文案没有「危险 / 泄漏」类恐吓措辞，读不到的数据不显示为 0
- [ ] 典型路径约 30 秒内能完成定位并退出
