# Pulse 产品需求（当前范围）

> 好看的 Mac 资源诊断器：外表像活动监视器，任务按诊断走。内存是主线，CPU、磁盘、网络和本机页提供同一套冷静读数。

仓库 [qqzhangyanhua/pulse](https://github.com/qqzhangyanhua/pulse)。暂名 Pulse，正式品牌待定。栈：SwiftUI 原生，公证直装，不做 Electron。

这份文档写**当前**范围和验收。新需求落地后，在同一个 PR 里更新这里。一期的原始需求见 [specs/00-prd.md](specs/00-prd.md)。实现细节见 [TECH.md](TECH.md)。

## 问题与用户

macOS 自带的活动监视器信息密度高，很难一眼看出「谁在吃内存、压力是否偏高」。用户需要一个好看又好用的本地工具，在卡顿或内存吃紧时快速找到并处理进程。

| 项 | 内容 |
| --- | --- |
| 主用户 | 日常 Mac 用户和开发者（同一界面） |
| 情境 | 机器变慢、内存压力升高、怀疑某个 App 占用异常 |
| 要完成 | 看清总览，找到嫌疑进程，安全退出或强制退出 |
| 平台 | 仅 macOS 14+ 桌面端 |

## 定位与成功标准

- 默认进入内存页，进程表按内存占用降序。
- 压力状态优先展示（正常 / 偏高），文案冷静，没有吓人的告警。
- **成功标准**：用户能在约 30 秒内定位吃内存的进程并安全退出。

## 当前范围

| 模块 | 要求 |
| --- | --- |
| 内存页 | 用量大数、分类条、压力档与曲线、可用 / 交换 / 占用最多的 App；进程表（名称、CPU、内存、线程），默认内存降序；名称过滤、仅上涨、仅窗口 App、按 App 合并 |
| 进程内存 | 按内存占用（footprint）显示，读不到时回退驻留内存并标明 |
| 上涨信号 | 选中进程的「内存趋势」软信号；列表前 5 名的「上涨」徽标；不判泄漏 |
| 详情侧栏 | 图标与名称；当前页的主读数；内存主曲线、CPU 辅曲线；常见系统进程的一句说明；退出（主）/ 强制退出（次，系统确认）；退出后的已用内存变化 |
| CPU / 网络 / 磁盘页 | 主机读数与历史曲线；CPU 页含最忙一核；磁盘页读取 / 写入分列排序；进程网络速率暂不提供 |
| 本机页 | 机型、芯片、系统、容量、开机时间、电源、磁盘剩余、交换与当前负载；有内置电池时显示循环次数、健康度和功率；诊断项可跳到对应页 |
| 菜单栏 | 压力色点，默认栏上无文字；设置可选色点 + 已用内存或色点 + CPU（缺失为「—」，重启后保留）。轻量条：压力、已用内存、最忙一核（≥ 90% 时）、Top3 进程、打开 Pulse、设置 |
| 体验 | 前台采样约 1.5 秒；降频提示；键盘快捷键；记住主窗尺寸；尊重减少动态效果 |
| 分发 | 公证直装；Hardened Runtime；不做 App Store 沙盒 |

## 关键状态（必须有）

无选中空态；采样中；采样失败（可重试）；进程列表读取失败；压力正常 / 偏高；过滤无结果（可一次清空）；退出中 / 失败；读数缺失显示「—」而不是 0。

## 验收标准

逐项清单见 [TECH.md「本机冒烟清单」](TECH.md#本机冒烟清单)。产品层面的底线：

- [ ] 冷启动在内存页，进程表按内存降序
- [ ] 过滤和开关组合后列表正确，无结果有空态
- [ ] 选中进程后侧栏曲线正确，切换进程后重采
- [ ] 退出走 `terminate`；失败后可强制退出，且有系统确认
- [ ] 前台采样约 1–2 秒，自身无明显卡顿、占用克制
- [ ] 文案没有「危险 / 泄漏」类恐吓措辞，读不到的数据不显示为 0
- [ ] 典型路径约 30 秒内能完成定位并退出

## 明确不做

- GPU 页（Tab 栏不显示）
- 按进程的网络速率（系统没有可用的非特权来源）
- 自动判定内存泄漏
- 跨设备、登录项清理、分享
- Electron / 多平台、App Store 沙盒版、TCC 全盘访问、内核扩展、Helper / XPC
